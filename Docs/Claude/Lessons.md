# Lessons

> 반복하지 않을 실수와 바로 따를 행동. 형식 : `상황 → 행동` (왜 : 과거 실수)

## 운영 규칙

- 정착된 교훈은 원래 규칙 문서로 옮기고 여기서 지운다. (이 문서는 아직 정리되지 않은 최근 실수만 둔다)
- 항목이 15개를 넘으면 위 정리를 사용자에게 제안한다.
- 한 주제의 교훈이 쌓이면 별도 문서로 분리해 `CLAUDE.md`의 On-Demand 참조에 등록한다.

---

1. 클라우드 MCP에서 Unity 엔진을 찾지 못함 → Unity 프로젝트 폴더에서 `unity-mcp-cli.cmd status`로 로컬 연결부터 시도한다. 둘 다 실패할 때만 보고한다.
    - 왜 : 바로 "연결 안 됨"으로 보고해서 작업이 멈췄다.
2. 결과를 바꾸는 CLI 명령(mutate, script-execute) 실행 → 필터 없이 `2>&1 | Out-String`으로 전체 출력을 받는다.
    - 왜 : 출력을 걸러서 에러를 놓쳤고, 같은 명령을 다시 실행하다 Scene 상태가 바뀌었다.
3. RQL로 enum 플래그 2개 이상 조합 → 처음부터 `script-execute`에서 C# 비트 OR로 지정한다.
    - 왜 : 문자열과 숫자로 반복 시도해 4번 만에 성공했다.
4. 시도가 실패함 → 에러 메시지의 제약을 읽고 다른 방법으로 바꾼다. 같은 방식의 변형을 반복하지 않는다.
    - 왜 : 3번처럼 같은 접근을 반복했다.
5. `script-execute`에서 로컬 함수 작성 → 바깥 변수를 쓰지 않고 모든 값을 매개변수로 넘긴다.
    - 왜 : CS0103 컴파일 에러가 나서 다시 작성했다.
6. 사용자가 제안한 구조(이벤트·주기 탐색 등)를 브리핑에 넣음 → 현재 코드·설계서 기준 문제점(계약 정합성, 오래된 참조, 구독 수명, 실측 근거)을 먼저 검토해 브리핑의 `설계 선택 검토`에 함께 보고한다.
    - 왜 : W04에서 0.1초 간격 이벤트 감지를 검토 없이 권장안으로 적었고, 발사 순간 판정 계약 위반·측정 없는 변경을 놓쳤다.
