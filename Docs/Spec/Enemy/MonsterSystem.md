## 0. 결정 표기 / 우선 적용 원칙

- **[확정-최신]** 이번 사용자 메시지에서 확정한 정책. 기존 GDD/Boss와 충돌하면 최신 정책 우선.
- **[확정-기존]** 원본 GDD·Boss·메모에 있는 정책 중 이번 요청과 충돌하지 않는 사항.
- **[권장-승인대기]** 구현을 단순하게 하기 위한 제안. Agent는 사용자 승인 없이 기획을 확정하지 않음.
- **[수치미정]** 인스펙터/SO 노출 후 플레이 테스트로 결정할 항목.

**문서 동기화 (완료 #8):** `GDD.md` 및 `Boss.md`의 최종 보스 생존 클리어를 **180초(3분)**로 반영했다. 즉 20:00 출현, **23:00 생존 클리어**, 또는 그 전에 보스 처치 시 즉시 클리어. 기존 4~5분 처치 목표는 3분 생존 클리어와 양립하지 않으므로 **밸런스 목표 재검토 대상**이다.

**Agent 수정 금지 영역:** 직접 구현한 Flow Field / Vector Field / Spatial Hash / Separation 및 인벤토리 격자·합성·인접 알고리즘. Agent는 기존 인터페이스를 조사하고 변경 필요 시 승인 요청. 사전에 합의되지 않은 자체 이동 알고리즘으로 대체 금지.

### 1.1 일반 3종 능력치

- **[확정-최신]** A/B는 서로 **다른 HP와 이동속도**를 가지되, 구체 차이폭을 지금 확정하지 않는다. 따라서 3종 랜덤 생김새/체력/속도여도 괜찮다. 중요한 부분은 전부 같은 이동속도와 체력만 아니면 된다.
- **[확정-기존]** C는 A/B보다 빠르며 체력은 상대적으로 낮다. 얼마나 차이나는지는 **[수치미정]**.
- **[확정-기존]** 기준 느린 몬스터에 대한 목표 체감: Lv.1 기본 권총 약 2발 / 미니건 약 5발 / 샷건 약 3개 **개별 펠릿 적중**으로 사망하도록 밸런스 검토. 개별 무기 피해량과 펠릿 수에 따라 모든 조건을 동시에 충족하지 못할 수 있으므로 **HP 자체는 테스트로 결정**한다. 몬스터별 무기 예외 피해 규칙은 추가하지 않는다.
- **[확정-최신]** 일반 A/B/C는 **사망 시 경험치 젬 1개씩** 드롭한다. 지급 XP 값은 레벨or시간ordps에 따라 지급량 다름 or 지급량 시간or레벨에 따라 변화하며 최대 레벨 고려하여 몬스터 수도 조절, 나은 방향 제안(밸런스 문제).
- **[확정-기존]** Bat의 공중 비행은 **외형 연출만**; 실제 이동·감지·피격·접촉 기준은 지상 몬스터와 동일. 렌더 자식 Y 오프셋 방식은 **[권장-승인대기]**.
- **[확정-최신]** 외형, Move/Death 애니메이션 연결은 **P0 필수**. 원본 에셋의 실제 애니메이션·리깅 유무와 프리팹 계층을 Agent가 확인할 것. 원본에 없는 클립을 임의로 있다고 가정하지 않음.

## 2. 공통 몬스터 생명주기 — P0

1. 풀에서 몬스터 소환 → 종류별 HP, 이동속도, 접촉 피해, Animator 상태, Collider, 이벤트/타이머 등 **완전 초기화**.
2. 기존 Flow Field로 플레이어 추적. Alive 상태에서만 피해와 이동 활성화.
3. 무기 탄환 피격 시 기존 Damage API로 HP 감소. 중복 Collider를 가진 적도 **한 번의 유효 타격은 한 번만** 처리.
4. HP 0 이하 시 사망 **단 한 번** 확정. 추적·접촉 공격·추가 피격 정지 → 타입별 드롭 1회 요청.
5. Death 애니메이션 재생 후 풀 반환. 애니메이션 이벤트 누락 시 반환 불가 상태가 지속되지 않도록 **fallback** 마련.
6. 풀 재사용 시 사망 플래그·코루틴·이벤트·이전 타깃 및 상태 초기화. Death 연출 중 재사용 불가.

**드롭 규칙:**
- 일반 A/B/C: `BTM_Assets/Ruby2` **1개**.
- 강화 몬스터: 노란 재질(`BaseMaterial_Yellow`)을 입힌 Ruby2(금색 젬) **1개**, XP **10** (일반 몬스터 XP 1 기준 10배, Q07 결정, 구현 #19).
- 5/10/15분 보스: `Low Poly Toon Chests/Silver_Chest` **1개**, 경험치 젬 미드롭.
- 최종 보스: 처치 즉시 클리어, 보상 상자/젬 추가 요구 없음.

젬은 **드롭 즉시 XP 지급이 아니라**, 수집 반경 진입 → 플레이어 Pivot으로 이동 → 중심 도달 시 XP 지급·효과음이 발생한다. XP 수집은 기존/별도 경험치 시스템과 API 연동하며 몬스터 스크립트에서 직접 XP를 올리지 않는다. 풀링을 활용하되 기존 공용 풀 재사용 가능 여부를 먼저 조사한다.

- **[확정-최신]** 경험치 젬은 수명이 없다(수집될 때까지 유지). 이후 추가할 "맵 전체 젬 배달" 소비 아이템은 흩어짐 없이 바로 플레이어 중심으로 이동해 획득된다.
- **[확정-최신]** 젬 획득 연출: 수집 반경 진입 직후 플레이어 반대쪽 범위의 랜덤 방향으로 살짝 멀어졌다가 플레이어 중심으로 흡수된다.
- **[확정-최신]** 레벨업 요구 경험치는 임시 곡선 `5 + 5×(레벨−1)`을 사용하며 밸런스 단계에서 재결정한다. 레벨업 일시정지·보상은 후속 작업이다.
- **[확정-최신]** 몬스터 피격 데미지 숫자는 실제 깎인 체력이 아니라 **들어온 피해량(오버킬 포함)**을 표시한다.

### 2.1 접촉 피해 — 플레이어 공통 무적 게이트

- **[확정-최신]** 아래 추천 정책을 승인된 결정으로 채택한다. 플레이어 공통 무적 게이트, 무적 0.5초(Inspector 조절), 소유자 `Assets/Scripts/Player/PlayerHealth.cs` (구현 #8).

**문제:** 다수 몬스터 Collider가 동시에 플레이어와 겹칠 때 프레임마다 또는 몬스터별로 피해가 중첩되면 플레이어가 즉사할 수 있다.

**추천 정책 (P0): 플레이어 공통 피격 무적시간 + 접촉 판정 게이트**
- 몬스터 접촉 시 플레이어가 피해 가능 상태라면 **한 번만** 피해를 적용하고, `contactInvulnerabilityDuration` 동안 몬스터의 추가 **접촉 피해**는 무시한다.
- 무적시간은 **플레이어 HP/피해 수신 시스템이 소유**한다. Enemy마다 독립 타이머를 두지 않는다.
- 같은 프레임에서 10마리가 접촉해도 동일 피해 수신 창에서 한 번만 피해가 발생하도록 한다.
- 무적 중 몬스터는 계속 이동·겹침 가능. 접촉 종료를 기다리지 않고 무적시간이 끝났을 때 여전히 접촉 중이면 다시 타격 가능하도록 설계할 수 있다.
- **권장 초기 테스트값:** 0.5~1.0초 범위(고정 확정 아님). 피해량, 무적 시각 효과는 별도 결정.
- **[확정-최신]** 보스 돌진·탄환 피해도 같은 공통 피격 무적 게이트를 공유한다 (Q04 결정, 구현 #19 : 돌진은 기존 접촉 피해, 탄은 `PlayerHealth.TakeDamage`). 방어/회피 밸런스에 맞춘 조정은 후속.
- 기술적으로는 `OnTriggerEnter`만 사용하면 접촉 유지 상태에서 재타격되지 않을 수 있다. 기존 Player/Enemy 콜라이더 구성에 맞게 `OnTriggerStay` 또는 접촉 목록 기반 주기 확인을 비교해 **한 방식만 선택**.

**대안:** 몬스터별 접촉 쿨다운만 적용하면 여러 마리가 동시에 각각 공격하여 총 피해가 폭증할 수 있으므로, 현재 게임의 다수 스폰 구조에는 비추천.

- **[확정-최신]** 접촉 피해가 0인 적은 구현 계획이 없다.

## 3. 일반 스폰 / 상한 — P0

| 시간 | 일반 랜덤 후보 |
|---|---|
| 00:00~02:59 | A |
| 03:00~05:59 | A, B |
| 06:00 이후 | A, B, C |

- **[확정-최신]** 일반 몬스터는 플레이어 주변 **Game View 카메라 밖**에서 생성한다. 경계 바로 바깥 거리, 지형·통행 가능 셀 조건은 **[수치미정]**.
- 초기에는 후보 종류를 균등 랜덤으로 제안. 가중치, 시간별 기본 스폰 주기·개수는 Inspector에서 조정하고 승인 후 적용.
- **[확정-최신] 동시 활성 몬스터 최대 500마리.** Agent는 스폰 후보 수를 더하기 전에 활성 수 확인. 풀에 보관된 비활성 객체는 활성 수에 포함하지 않음.
- **[확정-최신]** (Q03 결정, 구현 #19) 500은 일반/강화/보스를 모두 합산한 전역 활성 상한이다. 보스·강화몹은 상한 검사 없이 예정 시각에 생성하고, 일반 랜덤 스폰과 원형 스폰은 보스·강화몹 스케줄 길이(현재 7)만큼 슬롯을 항상 예약한 상한(500 − 7 = 493)에서 멈춘다. 보스를 누락하거나 기존 적을 삭제하지 않는다.
- **[확정-기존]** 04:00 / 08:00 / 12:00 / 16:00에 **저속 일반 몬스터 다수 원형 스폰**을 진행하고 일반 랜덤 스폰도 계속 진행(상한에 걸릴 때만 조절). 당시 플레이어 위치 중심, 균등 각도, 맵 내 이동 가능 위치 사용 (구현 #19 채택). **P1 기능**.
    - **[확정-최신]** (구현 #19) 원형 스폰 전용 저속 개체 `Golem`(`PFB_EnemyGolem`, 일반 스폰 후보에는 없음)을 쓴다. 카메라 밖 조건은 두지 않는다. 회차마다 한 프레임에 일괄 생성하며, 통행 불가 지점은 그 1마리만 건너뛴다. 상한은 일반 스폰과 같다(위 상한 항목, Q03).
    - **[확정-최신]** Golem은 Separation 가중치가 낮아(현재 0.1, 일반 몬스터 1) 자신이 주변 Enemy(다른 Golem 포함)를 피하는 정도가 작다. 그래서 Golem끼리 덜 퍼지고 벽처럼 조여 온다. 가중치는 각 Enemy가 자기 이동에만 적용하므로, 일반 몬스터는 자기 가중치(1)로 Golem을 계속 피한다. 가중치 값은 **[수치미정]**.
    - 미정 : 일반 몬스터가 Golem 사이를 지나가지 못하게 할지는 게임 구현 후 밸런싱 단계에서 다시 확정한다 (현재 동작은 사용자 의도와 일치).
    - **[수치미정]** 회차당 수량·원 반지름. 현재 임시 값 50마리·반지름 25.
- 스폰 스케줄은 레벨업·상자 정리 중 멈추고, 정지/재개 후 같은 시각 이벤트가 중복 실행되지 않아야 한다.

## 4. 강화 몬스터 (`Elite`, 가칭) — P1

- **[확정-최신]** 보스가 아닌 강화 일반 몬스터. 기본 3종보다 높은 HP, 이동속도는 기본 3종보다 느림 (원형 스폰 전용 Golem은 비교 대상이 아님). 기본 몬스터 XP의 **10배**를 준다 (구현 #19 : XP 10, 일반 몬스터 1 기준, Q07).
- **[확정-최신]** 생성 위치는 직사각형 맵 상·하·좌·우 네 경계의 중점 중 **카메라 시야 밖이면서 플레이어와 가장 가까운 한 곳**이며, 이벤트마다 **1마리**가 등장한다 (Q01 결정). 이전의 "네 중점마다 1마리씩, 총 4마리 동시 등장" 해석은 **폐기**한다.
- **[권장-승인대기]** 5/10/15분 중간 보스보다 2분 빠른 **03:00/08:00/13:00에 각 1회 이벤트**를 실행. 이전 추천대로 **18:00 이벤트는 제외**하며 별도 주기적 재등장은 처음 구현하지 않음. 단, 원본의 '일정 시간마다'를 추후 반복 출현으로 확장할지는 미정. (구현 #19 : 이 시각으로 임시 채택, Q02)
- **맵 밖 등장 기술 이슈:** 기존 100×100 등 그리드 경계 *바깥*은 Flow Field 이동 방향이 정의되지 않을 수 있다. **[권장]** 화면상 생성 위치는 경계 외부에 두되, 첫 유효 셀까지의 짧은 진입만 별도 처리하거나, 플레이 가능한 경계 셀에 논리적 이동 개체를 두고 외형만 경계 바깥에서 들어오는 것처럼 연출. **Agent는 기존 Flow Field를 수정하거나 맵 밖으로 인덱싱하지 않는다.** 구현안·충돌 가능성을 먼저 보고하고 승인 받는다.
    - 구현 (#19) : 격자 안쪽 가장자리 행·열의 통행 가능한 변 중점 타일에 생성한다. 맵 밖 진입 연출은 없고 Flow Field는 수정하지 않았다. 보스도 같은 위치 규칙을 쓴다.
- **[확정-최신]** 강화 외형 3종 : `MonsterPlantPADefault`(03:00), `DragonPADefault`(08:00), `OrcPADefault`(13:00). 정식 이름은 정하지 않고 `Elite`(가칭)를 쓴다. 드롭 젬은 노란 재질 Ruby2(금색 젬) 1개.
- 강화 몬스터가 맵 중앙으로 플레이어를 반드시 이동시키는 새 강제 기믹은 구현하지 않는다. 맵 경계 쪽에서 진입해 압박하는 게임플레이 의도를 테스트한다.

## 5. 보스 공통 정책 — P0

| 게임 시각 | 외형 | 패턴 | 사망 / 클리어 |
|---|---|---|---|
| 05:00 | `SalamanderPADefault` | 빨간 돌진 경로 예고 → 준비 → 돌진 | Silver_Chest 1개 드롭 |
| 10:00 | `NagaWizardPADefault` | 짧은 예고 후 느린 직선탄 | Silver_Chest 1개 드롭 |
| 15:00 | `BishopKnightPADefault` | 느린 360도 균등 방사탄 | Silver_Chest 1개 드롭 |
| 20:00 | `BlackKnightPADefault` | 빠른 이동, 돌진 + 직선/부채꼴탄 | 처치 즉시 클리어 / 23:00 생존 클리어 |

- 보스 사전 등장 알림·카운트다운 UI는 구현하지 않는다. 각 시간에 **이전 보스가 살아 있어도** 다음 보스를 생성한다.
- 일반 몬스터와 동일한 HP·등록·이동 및 풀링 기반을 재사용. **돌진 상태와 Flow Field 추적을 동시에 적용하지 않는다** (구현 #19 : 보스 패턴이 경고·돌진·정지 사격 동안 `EnemyMovement.enabled`를 끄고, 끝나면 다시 켠다).
- 모든 공격 타이머는 **전투 게임 시간**을 사용. 레벨업·보상 일시정지 중 보스 탄환 이동과 공격 중단.
- 보스 감지 범위·체력·속도·패턴 쿨다운 등은 Inspector/SO로 관리하고 사용자 승인 없이 게임 밸런스 확정 금지.

### 5.1 5분 보스 — 돌진 (구현 #19)

1. 돌진 범위 밖이면 기존 Flow Field로 플레이어를 추적.
2. 돌진 조건을 만족하면 플레이어 방향을 스냅샷하고 빨간 선으로 경로를 보여줌.
3. 짧은 대기(경고 시간) 후 스냅샷 방향으로 직선 돌진, 종료 후 추적으로 복귀. 경고·돌진 동안 Flow Field 추적은 끈다.
4. **[확정-최신]** 돌진 중 플레이어 위치를 다시 추적하지 않음(보고 회피 가능). 빨간 선은 LineRenderer로 표시한다.
5. **[확정-최신]** 돌진은 정해진 거리에 도달하거나, 다음 위치가 장애물·격자 밖 등 이동 불가 칸이면 그 자리에서 끝난다. 돌진 피해는 별도 판정 없이 기존 접촉 피해를 쓴다. 준비 모션 애니메이션은 없다.
6. **[수치미정]** 돌진 거리·속도·경고 시간·쿨다운·감지 범위. 보스 넉백 저항은 현재 넉백 기능이 없어 다루지 않는다.

### 5.2 10분 보스 — 직선탄 (구현 #19)

- 감지 범위 내 플레이어가 있으면 짧은 예고(대기) 후 **1발의 느린 비유도 직선 투사체**를 발사.
- 발사 순간의 플레이어 방향으로 쏜다. 발사 후 유도·방향 변경 없음.
- **[확정-최신]** 보스는 멈추지 않고 이동하며 발사한다. 경고선 등 예고 표시는 없다.
- **[수치미정]** 감지 범위·예고 시간·발사 간격·탄속·피해량.

### 5.3 15분 보스 — 방사탄 (구현 #19)

- 감지 범위 안에 플레이어가 있을 때, **보스 중심 XZ 평면에서 360도 균등 분할된 방향으로 방사탄** 발사.
- **[확정-최신]** **8발**(45도 간격)의 느린 비유도 투사체를 동시에 발사 (8발은 임시 확정, 추후 수치 밸런싱에서 조정). 예고부터 발사까지 보스는 멈추고, 발사 후 추적으로 복귀한다. 예고 표시는 없다.
- **[수치미정]** 감지 범위·예고 시간·발사 간격·탄속·피해량.

### 5.4 최종 보스 — 복합탄 (구현 #19)

- 빠른 이동 + 5분 보스의 돌진 메커니즘 재사용. **[확정-최신]** 이동속도는 일반 C(Bat)보다 빠르다 (현재 4.5, Bat 4. 수치는 **[수치미정]**).
- **[확정-최신]** **돌진 → 직선 1발 → 돌진 → 부채꼴 3발**(플레이어 방향 중심 40°, -20°/0°/+20°)을 이 순서로 반복한다. 부채꼴 40°는 임시 확정이며 추후 수치 밸런싱에서 조정한다. 비유도 탄환이며 15분 보스의 전체 360도 방사와 다르다.
- **[확정-최신]** 패턴은 한 번에 하나만 실행하고, 한 패턴이 끝나면 정해진 간격(현재 1.5초) 동안 추적만 한 뒤 다음 패턴으로 넘어간다. 각 패턴은 플레이어가 그 패턴의 감지 범위에 들어와야 실행되므로, 범위 밖이면 그 차례에서 기다린다. 사격 패턴은 이동하며 발사한다.
- **[수치미정]** 패턴 간격·탄속·돌진 값.

### 5.5 보스 처치 예상 시간과 승리 조건

- 5분 보스 약 1분, 10/15분 보스 약 2~3분은 **밸런스 목표(스탯 확정 아님)**.
- **[확정-최신]** 최종 보스는 20:00 등장, **3분(180초) 생존 시 23:00 클리어**, 또는 그 전에 처치하면 즉시 클리어. 보스 등장 후 일반 적 생성도 계속된다.
- 구현 현황(이슈 #8): 생존 클리어 시각은 `GameSession`의 `_clearTime`(기본 1380초 = 23:00, Inspector 조절)으로 판정한다. 최종 보스 처치 클리어는 이슈 #19(M10)에서 구현했다 (처치 시 `GameSession`이 즉시 클리어 처리).
- 기존의 '성장한 캐릭터도 4~5분 공격해야 처치'는 23:00 생존 클리어와 충돌하므로 **현재 규칙상 처치 가능한 목표 시간을 3분 이내로 재설정할지** 추가 결정이 필요. Agent가 임의로 HP를 조정해 기존 목표를 보장한다고 보고하지 말 것.

### 5.6 보스 사망 보상 / 대기 레벨업 우선

1. 중간 보스 사망 시 HP/사망 확정 → 경험치 젬 없이 `Silver_Chest` 1개만 드롭.
2. 플레이어가 상자와 접촉하면 **상자 획득 요청**. 현재 대기 중인 레벨업 회차가 있으면 **모든 레벨업을 먼저 순차 처리**.
3. 그 후 상자 보상/인벤토리 화면(4칸 선택 확장 + 후보 5개 중 최대 3개)을 연다.
4. 상자 접촉 이전에는 확장권을 즉시 지급하지 않으며, 한 상자로 보상 창이 두 번 열리지 않는다.
5. UI 및 Inventory 내부 로직은 해당 시스템 소유자가 구현. Monster/Boss 측은 **상자 생성 및 보상 요청 이벤트**까지만 담당한다.

## 6. P0 / P1 / P2의 분류 기준과 실행 계획

### 6.1 기준

- **P0: 게임 필수 전투 루프 및 사용자에게 바로 보이는 핵심 기능**. 없으면 무기 공격·피격·경험치 성장·보스 승패를 확인하기 어렵거나 사용자 명시한 기본 외형·애니메이션 요구를 충족하지 못함.
