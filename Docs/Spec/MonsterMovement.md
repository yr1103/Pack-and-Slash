## 계약

### Enemy 생명주기
- `EnemySpawner`는 몬스터 스폰 요청과 스폰 타이밍을 담당한다.
- `EnemyPool`은 몬스터 인스턴스의 대여 및 반환을 담당한다.
- `EnemyManager`는 활성 몬스터의 등록·해제와 생명주기 이벤트 발행을 담당한다.
- `Enemy`는 체력, 피격, 사망 상태를 관리하고 사망 사실을 알린다.
- `EnemyManager`는 등록 및 해제 이벤트를 통해 몬스터 이동·공간분할 시스템에 생명주기 변화를 통지한다.
- 사망 시 **즉시 전투 대상에서 제외하고 Spatial Hash에서도 즉시 제거**하며, 사망 연출 종료 후 오브젝트 풀에 반환한다.
- **보스도 일반 몬스터와 동일하게** `EnemyManager` 등록·해제와 Flow Field / Spatial Hash 이동 체계를 따른다. 보스는 처치 시 경험치 보석 없이 **보물상자만** 드랍한다(`Boss.md`).
- 화면 밖 제거, 강제 디스폰, 씬 종료 등 사망 이외의 해제 상황도 처리하되 사망 보상을 지급하지 않는다.
- 등록 및 해제 처리는 중복 실행되지 않아야 한다.

### 이동
- 일반 몬스터는 Flow Field / Vector Field가 제공하는 방향으로 **각 enemy의 speed**만큼 이동한다.
- **lerp 이동 몬스터:** 플레이어 위치를 향해 **시간 기반 보정**한 lerp로 이동한다. 플레이어에게 변칙적으로 위협을 주는 몬스터로 가끔 등장한다. 구현이 복잡해지면 보류 또는 삭제할 수 있다.
- Flow Field 완성 전에는 Agent가 **매우 단순한 임시 추적 이동**을 사용한다.

### 이동 상태 (넉백·돌진)
- 상태 기반 이동 우선순위 제어와 이동 벡터 분리 방식을 적용한다.
- 넉백·돌진 중에도 몬스터를 Flow Field / Spatial Hash에서 등록 해제하지 않는다. 이동 상태에 따라 **어떤 이동 로직을 실행할지만** 결정한다.

### 타겟팅
- 무기의 대상 탐색은 Spatial Hash 조회를 사용한다.

### 맵 데이터
- Scene 단계에서는 Flow Field를 완성하지 않고, Flow Field가 필요로 하는 맵 데이터를 `MapGridProvider`가 정확히 제공하도록 만든다.
- 개발자가 데이터 형식을 확정하기 전까지 `MapGridProvider`는 **임시 형식**으로 작성한다. 임시 형식은 개발자 확정 후 **반드시 수정해야 하는 대상**이며, 코드에도 임시임을 표시한다.

### 작업 경계
- Flow Field 및 Spatial Hash 알고리즘의 내부 자료구조와 갱신 방식은 개발자가 직접 설계한다.
- AI Agent는 개발자 승인 없이 알고리즘 구현 영역을 변경하거나 해당 영역에 직접적인 의존성을 추가하지 않는다.
- 시스템 간 인터페이스 변경이 필요하면 구현 전에 변경안을 제시한다.

## 테스트 기준

- **생명주기:** 사망 즉시 전투 대상·Spatial Hash 제외, 연출 후 풀 반환, 사망 외 해제 시 보상 미지급, 등록·해제 중복 없음
- **이동 상태:** 넉백·돌진 중 등록 유지, 상태 종료 후 일반 추적 복귀
- **성능:** 몬스터 수별 CPU 시간, FPS, 이웃 탐색 횟수, GC, 겹침 현상. 기본 구현과 알고리즘 적용 결과를 같은 조건에서 비교

## 미정 파라미터

- 내부 자료구조·갱신 주기·이동 처리 방식 : 개발자가 실험을 통해 결정
- `MapGridProvider`의 데이터 형식 : 개발자 확정 후 Agent가 임시 형식을 수정한다
- lerp 이동 몬스터의 장애물 처리 및 등장 빈도 : Roadmap 7단계 브리핑에서 결정
