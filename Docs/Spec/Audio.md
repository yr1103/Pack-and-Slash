# Audio Spec

> 사운드가 필요한 상황과, 게임 로직과 사운드를 연결하는 방식.
> 사운드 에셋·재생 시스템은 미구현. 각 기능은 구현할 때 아래 표의 이벤트를 먼저 만들어 두고, 사운드는 나중에 구독만 추가한다.

---

## 데이터

### 사운드가 필요한 상황

| 분류 | 상황 | 발생 시점 | 이벤트 소스 | 상태 |
|---|---|---|---|---|
| 무기 | 발사 (권총·샷건·미니건) | 발사 1회마다 | `WeaponInstance.AmmoChanged` (잔탄 소모 = 발사 1회) | 이벤트 있음 |
| 무기 | 재장전 시작 | 탄창 소진 | `WeaponInstance.ReloadStarted` | 이벤트 있음 |
| 무기 | 재장전 완료 | 재장전 종료 | `WeaponInstance.ReloadFinished` | 이벤트 있음 |
| 무기 | 탄 적중 | 적 피격 (피해 적용 시마다) | `Enemy.Damaged` (인스턴스 이벤트, 인자 피해량) | 이벤트 있음 |
| 적 | 사망 | 사망 확정 | `Enemy.Died` | 이벤트 있음 |
| 플레이어 | 피격 | 피해 적용 | `PlayerHealth.Damaged` | 이벤트 있음 |
| 플레이어 | 사망 | 체력 0 | `PlayerHealth.Died` | 이벤트 있음 |

| 성장 | 레벨업 | 레벨 조건 충족 (레벨업 1회마다) | `PlayerExperience.LevelChanged` (인자 새 레벨) | 이벤트 있음 |

## 계약

- 게임 로직(무기·적·플레이어·보스)은 사운드를 직접 재생하지 않는다. 상황이 일어나면 C# 이벤트만 발생시킨다.
- 사운드 재생은 별도 오디오 컴포넌트가 위 이벤트를 구독해 처리한다. 구독은 `OnEnable`/`OnDisable`에서 짝을 맞춘다.
- 새 기능을 구현할 때 위 표에 해당하는 상황이 있으면, 사운드가 없어도 이벤트를 만들어 두고 이 표의 `이벤트 소스`·`상태`를 갱신한다.
- 일시정지(레벨업·보상) 중에는 전투 사운드를 새로 재생하지 않는다. UI 사운드는 재생한다.

## 테스트 기준

- 이벤트 1회 발생 = 사운드 1회 요청 (예 : 젬 1개 획득에 획득음 1회, 같은 젬으로 중복 재생 없음)
- 사운드 컴포넌트가 없거나 클립이 비어 있어도 게임 로직은 정상 동작한다.

## 미정 파라미터

- 사운드 에셋 출처와 형식
- 동시 재생 제한 : 미니건 연사, 다수 적 동시 사망, 젬 대량 획득 때의 최대 동시 재생 수·쿨다운
- 볼륨 분류(BGM·전투·UI)와 조절 UI
- `WeaponInstance.AmmoChanged`를 발사음 트리거로 계속 쓸지, 발사 전용 이벤트를 따로 둘지
