> 장착 격자 인벤토리, 좌측 Storage, 배치·인접·합성, 셀 확장. **판정 로직은 개발자 담당** (`TechSpec.md` › `담당 경계`)
> 관련 GDD : §7, §8, §10

## 데이터

| 데이터 범주 | 최소 필요 정보 | 사용처 |
|---|---|---|
| 아이템 종류 정의 | 고유 종류 ID, 무기/패시브/필수 구분, 격자 형태, 기본 효과, 레벨별 효과 | 보상 생성, 배치, 표시 |
| 아이템 인스턴스 | 인스턴스 ID, 종류 ID, 레벨(해당 시), 보유 위치, 회전 상태 | 합성, 장착, 판매, Storage |
| Storage 상태 | 보관 중인 아이템 인스턴스 목록, 정규 한도 5, 현재 수량 | 좌측 패널, 초과 경고, 완료 검증 |

- **종류 ID와 인스턴스 ID는 구분**한다. 같은 종류의 무기 두 개도 별도 인스턴스로 관리한다.
- 아이템은 최소한 **장착 인벤토리 / Storage / 미처리 보상 / 제거됨(판매·합성 소비)** 상태를 구분한다. 한 인스턴스가 두 저장 위치를 동시에 점유할 수 없다.
- **아이템 종류 정의는 ScriptableObject로 만든다.** 격자 형태는 `Assets/Scripts/BlockPuzzle/PieceData.cs`처럼 피벗 (0,0) 기준 칸 좌표 배열 구조를 참고한다.

## 계약

### 공통
- UI는 인벤토리 로직이 제공하는 **조회/검증/확정 결과**를 사용하며, UI 단에서 배치·합성 규칙을 재구현하지 않는다.
- 배치 가능한 칸, 아이템 도형·회전 상태, 중복 인접 효과 대상은 데이터 기반으로 다룬다. 구체 컨테이너와 알고리즘은 개발자가 확정한다.
- **기본 인벤토리 크기는 4×4**로 시작한다.

### 전투와의 연결
- 인벤토리 구현 전에는 전투가 **임시 장착 목록**을 사용하고, 인벤토리 구현 후 인벤토리 구조로 교체한다. 임시 목록은 교체를 고려해 작성한다.
- 전투가 받는 확정 결과(장착 인스턴스, 인접 쌍, 변경 알림 등)의 형태는 인벤토리 구현 중에 확정한다.

### 배치·인접
- **배치:** 회전된 아이템이 사용 가능하고 비점유인 격자 셀에 완전히 들어가야 한다.
- **배치 불가 표시:** 배치할 수 없는 위치에 놓으면 해당 위치에 임시 배치한 채 아이템을 **빨간색**으로 표시하고, 이 상태가 남아 있으면 `완료`를 막는다. (실제 플레이 후 수정 여부 판단)
- **인접:** 상하좌우만 인정하고 대각선은 제외한다. 한 아이템 쌍이 여러 칸에서 접촉해도 동일 쌍의 효과는 1회다.
- **중복 패시브:** 서로 다른 패시브 인스턴스가 같은 무기와 인접하면 각각 효과를 적용한다.
- **장착 무기:** 동일 종류 최대 2개. (인스턴스별 공격은 `Combat.md`)

### 합성
- **조건:** `종류 ID 동일 AND 레벨 동일 AND 레벨 < 5`. `Lv.n + Lv.n → Lv.(n+1)`이며 레벨 합산이 아니다.
- **트리거:** 레벨업 정리 화면에서 새 보상 또는 Storage의 아이템을 대상에 드래그하면 유효성·결과 레벨을 미리 보여주고, 유효한 드롭 시 확정한다. **기존 아이템의 단순 인접·재배치로 자동 합성하지 않는다.**
- **합성 미리보기:** 합성 가능 시 결과 레벨과 레벨업으로 달라지는 효과 차이(예: 공격력 +10%)를 표시한다.
- **Storage 내부 및 Storage↔장착 인벤토리 간 드래그 합성**을 레벨업 정리 화면(일시정지 상태)에서 허용한다. 합성 판정 주체(인벤토리 알고리즘 / Storage)는 인벤토리 구현 중에 확정한다.

### Storage
- Storage는 장착 인벤토리와 **별개로 보관**한다.
- 레벨업 정리 화면에서 **좌측은 Storage 세로 목록, 우측은 격자형 장착 인벤토리**로 표시한다. 상세 UI 아트·해상도·드래그 프레임워크는 구현 브리핑에서 결정한다.
- **정규 한도는 아이템 인스턴스 5개**다. 격자 면적과 무관하게 한 인스턴스를 한 개로 센다.
- 정리 중에는 **6개 이상 임시 보유**가 가능하다. `Storage 7/5`처럼 현재 개수/한도와 초과 수량, 완료 불가 사유를 표시한다.
- 초과 상태에서도 판매·이동·합성·조건을 충족한 진화로 정리할 수 있다.
- 신규 보상은 장착, Storage 보관, 합성, 판매 중 하나로 처리한다. 보관된 아이템은 이후 정리 화면에서 장착·합성·판매할 수 있다.
- Storage에만 있는 아이템은 **공격·능력치·인접 시너지·진화 조건에 기여하지 않는다.** 장착 효과의 기준은 우측 격자에 배치 확정된 인스턴스다.
- 한 번의 이동/합성/판매는 정확히 하나의 소유 위치에만 반영한다. 중복 생성·유실·음수 수량을 허용하지 않는다.
- **전투 중에는 Storage 정리 불가.**

### 셀 확장
- 확장 후보는 **현재 사용 가능 영역의 외곽 기준 상하좌우** 칸이다. (기본 4×4 기준 각 변 1×4, 총 16칸)
- 플레이어는 후보 중 **원하는 칸을 자유롭게** 선택한다. 후보 칸은 UI 아이콘 변화로 표시한다.
- 확장 후 다음 후보는 확장된 외곽을 기준으로 다시 정한다.
- 확장 선택 중에는 `확장할 N칸을 선택하세요!!` 안내 문구를 표시하고, 남은 칸을 모두 선택하면 숨긴다. (1칸 확장권도 동일)
- 보스 상자 회차는 **확장 칸을 모두 선택해야 완료**할 수 있다. 후보가 부족하면 후보 수까지만 선택한다. (#23 사용자 결정)
- 확장 출처 : 중간 보스 처치 4칸(`Boss.md`), 1칸 확장권(`Reward.md`, 동일 방식), 캐릭터 보너스(`Combat.md`)
- 저장 구조와 확장 알고리즘은 개발자가 설계한다.

## 테스트 기준

- **가방:** 회전 후 경계/잠금/충돌 판정, 배치 불가 시 빨간 표시 및 완료 차단, 동일 종류·동일 레벨 합성, 다른 레벨 합성 거부, 합성 미리보기(결과 레벨·효과 차이), 장착 인스턴스 독립성
- **Storage:** 좌측 패널/우측 장착 격자, 인스턴스 5개 한도, 임시 초과(6/5 등) 허용, 초과 시 완료 비활성화, 정리 후 5개 이하에서만 완료, 다음 회차에서 꺼내기/합성/판매, 장착 효과 미적용, 아이템 유실·복제 방지
- **확장:** 외곽 후보만 선택 가능, 선택 수만큼 확장, 확장 후 후보 재계산
