## 1. 프로젝트 목표와 범위

### 1.1 학습 목표 (우선순위 1)
- **Vector Field / Flow Field:** 다수 몬스터의 플레이어 추적 이동을 위한 방향장 설계·적용 및 성능 검증.
- **공간분할 / Flocking:** Spatial Hash를 통한 주변 몬스터 탐색, Separation 중심의 겹침 완화 및 성능 검증.
- **격자 인벤토리:** 데이터 구조, 좌표·회전·배치·충돌 판정, 인접 시너지 탐색, 드래그 합성 가능 여부를 직접 설계·구현.
- 구현 결과를 몬스터 수, CPU 처리 시간, 탐색 횟수, GC 할당량 등으로 비교한다. 최적화 알고리즘이 언제나 유리하다고 가정하지 않는다.

### 1.2 AI 협업 목표 (우선순위 2)
Claude Code와 Codex를 컨텍스트 기반 하네스 엔지니어링 워크플로로 활용한다. 플레이어·무기·적 데이터, 투사체, 보스, 경험치, UI, 전투·게임 흐름 등은 Agent 지원으로 구현한다. 알고리즘 담당 부분은 Agent가 임의 수정하지 않으며 개발자가 승인한다. 기초 기능과 알고리즘 구현 후에는 인터페이스를 기준으로 병렬 통합한다.

### 1.3 기술 환경
| 항목 | 기준 |
|---|---|
| Unity | **6000.3.9f1** |
| 렌더링 | URP |
| 빌드 | Windows |
| 입력 | New Input System, `InputActionReference` 참조; `OnEnable()`/`OnDisable()`에서 Enable/Disable |
| 작업 도구 | Rider / Claude Code / Codex |
| 시점 | **3D 탑다운 뷰** / 맵 에셋 : Low Poly Nature Bundle (Unity Asset Store) |
| 아직 결정하지 않음 | 물리 이동 방식, 내부 폴더 구조 |

## 2. 핵심 플레이 루프 및 승패

1. 캐릭터 3종 중 1종 선택 → 해당 캐릭터의 시작 무기와 필수 인벤토리 아이템 장착.
2. 맵에서 WASD 이동, 장착 무기 자동사격, 일반 몬스터 무한 생성.
3. **일반 몬스터 처치 시 경험치 보석이 월드에 드롭**되고, 플레이어 몸에 닿은 보석은 플레이어 중심으로 이동하고, 도착 시 획득되어 경험치 게이지가 증가한다. (상세 §2.1)
4. 요구 경험치를 채워 레벨업하면 **전투와 생존 타이머를 일시정지**하고 레벨업/인벤토리 화면을 연다. 여러 레벨업이 누적된 경우 한 회차씩 보상 정리를 끝내고 다음 회차의 레벨업 연출·UI를 순차적으로 진행한다.
5. 무기·패시브·확장권·소비형 보상 후보 3개에서 **최대 2개까지 획득**한다. 장착·화면 좌측 **Storage(기본 보관 한도 5개)** 보관·동일 레벨 합성·판매·리롤·회전·재배치 후 `완료` 버튼으로 전투 재개한다. **Storage 보관 수가 5개를 초과하면 완료할 수 없다.**
6. 5분·10분·15분에 중간 보스가 각각 자동 등장. 처치하면 인벤토리 **4칸 확정 확장** 및 **보물상자(5중 3택)** 드랍.
7. 패시브와 무기의 배치 시너지, 특수 재화 리롤과 진화로 화력을 강화한다.
8. **20:00에 최종 보스 등장.** 최종 보스를 처치하거나 등장 이후 90초를 살아남으면 클리어. 플레이어 HP 0이면 게임 오버. 처치하지 않고 생존으로 승리할 경우 21:30에 클리어.

### 2.1 경험치 보석
- 일반 몬스터 사망 시 경험치 보석 오브젝트를 맵에 생성한다.
- **초기 크기가 플레이어 몸과 같은 수집 감지 Collider**에 보석이 들어오면 보석은 플레이어 **중심 Pivot**으로 빨려 들어가듯 이동한다. 중심에 도달했을 때 보석을 제거하고 경험치를 증가시키며 획득 효과음을 재생한다. 감지 시점에 경험치를 즉시 부여하지 않는다.
- 수집 범위가 증가하면 감지 Collider의 반경을 확대한다. 실제 흡수 이동·도착 판정의 세부 구현은 기술 설계에서 결정한다.
- 보석별 경험치량, 잔존 시간, 중첩·병합, 풀링 방식은 추후 결정.
- 패시브 **냉각기 Lv.3**의 획득 반경 증가는 플레이어가 보석을 수집할 수 있는 반경을 넓히는 효과로 해석하며, 실제 획득 처리와 연결한다.
- 인벤토리 일시정지 중에는 보석 이동·수집과 전투 관련 타이머도 진행되지 않는다.

### 2.2 UI 범위
- **전투 UI:** HP, 레벨, 경험치 게이지, 생존 시간, 특수 재화.
- **보스 등장에 대한 별도 사전 예고·시간 카운트 UI는 제공하지 않음.** 보스 자체와 공격은 실제 게임 공간에 표시한다.
- **레벨업 UI:** 후보 3개, 최대 2개 획득, 판매, 잔여 후보 리롤, 격자 인벤토리, 좌측 Storage, 회전·배치·합성 미리보기, Storage 초과 경고, 완료.
- **소비형 보상:** 체력 회복(+30 예시), 맵 전체 경험치 보석 수집(추가 구현 후보). 선택 즉시 효과를 적용하며 장착 인벤토리나 Storage를 점유하지 않는다.
- **종료 UI:** 클리어/게임 오버, 생존 시간, 처치 수, 최종 레벨.

## 3. 캐릭터 (초기 구현 3종)

| 캐릭터 | 시작 무기 | 필수 장착 아이템 | 크기 | 고유 특성 | 콘셉트 |
|---|---|---|---|---|---|
| 카우보이 | 권총 | 카우보이 모자 | 1×2 | 권총 공격력 +10% | '모자는 남자의 자존심' |
| 겁쟁이 생존자 | 샷건 | 전투 조끼 | 2×2 | 가방 확장 **+2칸** | 몸을 지키기 위해 조끼 착용 |
| 헤비거너 | **미니건** | 프로틴 또는 다른 1×1 아이템 | 1×1 | 이동속도 -10%, 미니건 정확도 +10% | 무거운 무기를 능숙하게 다룸 |

- 세 캐릭터는 공통 플레이어/전투 로직을 재사용하고 데이터와 시작 아이템만 다르게 한다.
- 시작 무기는 일반 무기와 같이 **회전 및 조건부 합성 가능**하다.
- 필수 아이템도 **이동과 회전 가능**. 필수 아이템은 **탈착·판매할 수 있다.** 탈착(Storage 보관 포함) 상태에서는 작은 버프와 **그보다 큰 디버프**를 받고, 재장착하면 원래 효과로 완전히 복구한다. 판매하면 재획득 전까지 탈착 상태가 유지된다. 탈착 효과의 초기 제안 수치와 전투 조끼 +2칸 회수 예외는 `WeaponSystem.md` §3.6을 따른다.
- 시작 무기도 판매할 수 있으며, 시작 무기 판매만으로는 필수 아이템 탈착 페널티가 생기지 않는다.
- 전투 조끼의 기본 가방 확장 보너스는 **+2칸**으로 적용한다.
- 헤비거너의 정확도 +10%는 미니건 **탄퍼짐 각도 0.9배**로 적용하는 것을 제안한다. (설계 제안, 최종 하한각은 밸런스 단계에서 결정)

## 4. 무기와 공격 성장

### 4.1 무기 공통
- 초기 무기: **권총 / 샷건 / 미니건** 총 3종. 과거 명칭('기관단총' 등)을 '미니건'으로 통일한다.
- 모든 무기는 **플레이어 중심 360°** 범위에서 무기별 감지 거리 안의 최근접 적을 독립 조준해 자동 발사한다. 탄은 **유도하지 않으며**, 권총·미니건 탄은 화면 밖에서 전투 효과를 내지 않는다. 상세 조준·발사·배치 규칙은 `Docs/Spec/Weapon/WeaponSystem.md`를 따른다.
- 각 무기 **Lv.1~5**. 레벨이 오르면 기본 공격력이 강화된다.
- **Lv.3 고유 효과**가 있으며 Lv.5의 별도 일반 고유 효과는 추가 구현으로 보류한다.
- 같은 종류의 무기를 인벤토리에 **최대 2개**까지 배치할 수 있고 각 무기 인스턴스는 독립 공격한다.
- 중복 장착 디버프는 **현재 미적용, 밸런스 후 결정**.

| 무기 | 기본 공격 | Lv.3 효과 | 진화 공격 (6장 참조) |
|---|---|---|---|
| 권총 | 단일 목표 자동 사격, **1.5초**마다, 재장전 없음 | 해당 무기 인스턴스가 **권총 2자루**를 사용 | **권총 4자루** 사용 및 **난사 스킬**(쿨다운 10초 / 지속 3초) |
| 샷건 | 근거리 산탄(부채꼴 균등 간격), **2.5초**마다, 재장전 없음 | 적중 시 **넉백** | 발사 범위/반경 확대, **4초**마다 **360도 방사형 사격** |
| 미니건 | 빠른 연사, 작은 부채꼴 범위에서 무작위 탄퍼짐, **탄창 100발 / 재장전 5초** | 발사 정확도 상승(탄퍼짐 감소) | 탄환 수 증가 및 **관통**(탄환당 서로 다른 적 최대 **3마리**, 초기값) |

- 위 수치는 초기값이며 인스펙터에서 조절한다. 공격력·감지 거리·사거리·탄속·탄퍼짐·넉백 세기는 밸런스 변수.
- 탄속은 상대적으로 샷건 빠름 / 권총 보통 / 미니건 느림이다.
- 장착 무기 중 **주무기 하나**만 손에 들고 캐릭터 몸통 회전을 제어하며, 나머지 총기는 플레이어 주변에 360° 균등 배치된 부유 무기로 독립 조준한다. 주무기는 인벤토리 UI에서 지정하며, 판매·해제 시 **진화 우선 → 높은 레벨 우선 → 먼저 장착한 순서**로 자동 승계한다.
- 샷건 넉백은 직접 구현할 이동 알고리즘과 연결하되, 충돌·이동 제어 통합 방식을 사전에 고정하지 않는다. 같은 발사의 다중 펠릿 적중 넉백에는 상한 또는 점감을 두고, 보스에는 넉백 저항 배율을 적용한다.

### 4.2 Lv.3 무기 두 개 장착 시 효과
- **같은 종류의 무기는 최대 2개까지** 장착하고 각 무기는 독립 발사한다.
- **Lv.3 효과는 무기 인스턴스마다 중복 적용한다.** 예: 권총 Lv.3 두 개를 장착하면 각각 2자루 효과가 적용되어 총 4자루가 발사한다.
- 중복 장착 디버프는 현재 미적용이며, 실제 플레이·성능 측정 후 검토한다.

## 5. 패시브 아이템과 인접 시너지

### 5.1 무기별 대응 패시브 (수정된 최종 조합)

| 패시브 | 대응 무기 | 기본 효과 | **패시브 Lv.3 추가 효과** |
|---|---|---|---|
| **개머리판** | **권총** | 공격속도 소폭 증가 | 경험치 획득량 소폭 증가 |
| **냉각기** | **미니건** | 정확도 소폭 증가: 부채꼴 발사 각도가 좁아짐 | 몬스터 처치 후 드롭된 **경험치 보석의 획득 반경 증가** |
| **탄띠** | **샷건** | 공격력 소폭 증가 | **이동속도 +10%** |

- Lv.1~5까지 존재하며 상위 레벨일수록 기본 효과 강도를 높이는 방향. **구체적인 기본 효과 수치와 증가 곡선은 미정**.
- Lv.3 추가 효과의 적용 대상(플레이어 전역인지, 인접 무기가 존재할 때만인지)은 구현 전 정의한다. 현재의 일반 시너지 규칙은 **대응 무기와 인접할 때 발동**한다는 전제다.
- 패시브와 대응 무기가 **상하좌우로 접촉**할 때 인접 시너지를 적용하며 대각선 접촉은 제외.
- 하나의 패시브 인스턴스가 같은 무기와 여러 칸 닿아도 해당 쌍의 효과는 **1회만** 적용.
- **서로 다른 패시브 인스턴스가 동일 무기에 각각 인접하면 중첩 허용**. 여러 무기와 맞닿는 경우 적용 범위 및 전역 효과의 중복 방식은 테스트 전 결정.
- 무기·패시브의 격자 점유 칸 수와 도형은 **미정**. 실제 UI와 직접 구현할 배치 알고리즘 설계 전 확정해야 한다.

## 6. 무기 진화

### 6.1 공통 조건
1. **대상 무기 Lv.5**.
2. **대응 패시브 Lv.5**.
3. 두 아이템이 인벤토리에서 **인접**.
4. 해당 진화에 필요한 **특수 재화 지불**.

- 진화는 단순 수치 증가가 아니라 **공격 패턴 변경**이다.
- **진화 시 아이템 점유 공간을 기존보다 1~2칸 늘리는 구조**를 검토한다. 확장 방향과 실제 크기, 확장 불가 시 처리 방식은 미정.
- 진화 재화는 무기 종류별 차등 비용 가능; 구체 가격 미정.

### 6.2 진화 종류
| 진화 조합 | 진화 결과 및 공격 특성 |
|---|---|
| **권총 + 개머리판** | 권총 **4자루** 보유 형태, **10초** 쿨다운마다 **3초** 동안 **난사 스킬** 발동 |
| **미니건 + 냉각기** | 발사 탄환 수 증가, 탄환에 **관통** 부여(서로 다른 적 최대 **3마리**, 초기값) |
| **샷건 + 탄띠** | 공격 발사 범위/반경 증가, **4초**마다 **360도 방사형 사격** |

- 위 주기·관통 수는 초기값이며 인스펙터에서 조절한다. 난사 탄 간격, 미니건 탄환 수 증가 방식·수량, 방사 탄 수·반경은 밸런스 단계에서 정한다.
- **구현 목표는 3종 진화**(첨부 v1의 최신 범위). 2주 일정 위험이 커지면 우선 1종 완성 후 나머지 2종을 확장할 수 있도록 동일 인터페이스로 설계한다.
- 진화 후 대응 패시브의 유지/소비 여부, 진화 무기를 일반 무기 중복 개수에 포함하는 방식은 미정.

## 7. 인벤토리 기본 규칙

- *Backpack Hero*식 격자 인벤토리: 사용 가능 셀, 잠긴 셀(사용 가능 영역 외곽의 확장 후보 셀, §10), 점유 셀을 구분한다.
- 무기·패시브·필수 아이템은 서로 다른 격자 형태를 가질 수 있으며 **90도 단위 회전** 가능.
- 드래그 중 범위·잠금·겹침·합성 가능 상태를 미리 표시한다.
- 기존 장착 아이템은 재배치할 수 있다. **기존 아이템끼리 닿거나 겹치는 것으로 자동 합성되지 않는다.**
- 서로 다른 종류의 아이템은 합성할 수 없으며, 서로 겹치는 위치에 일반 배치도 불가능하다.
- 무기·패시브 시너지 계산은 최종 배치 상태의 인접 관계로 판단한다.
- 시작 인벤토리는 **4×4**다(§10). 최종 가방 외곽 범위, 아이템별 크기·도형은 현재 미정이다.
- 아이템 종류 정의는 ScriptableObject로 만들고, 격자 도형은 테트리스 블록처럼 피벗 기준 칸 좌표로 표현한다.
- 배치할 수 없는 위치에 놓은 아이템은 그 위치에 임시 배치된 채 **빨간색**으로 표시되며, 이 상태에서는 `완료`할 수 없다. (실제 플레이 후 수정 여부 판단)

## 8. 동일 아이템 합성 — **이번 개정의 핵심 변경**

### 8.1 합성이 발생하는 경우
- **레벨업 보상 또는 보관함에 보관된 아이템**을 사용자가 드래그하여, **장착 인벤토리 또는 보관함의 동일 종류·동일 레벨인 아이템 위에 놓았을 때** 합성한다.
- 드래그 중 **합성 가능 표시와 결과 Lv. UI**, 레벨업으로 달라지는 효과 차이(예: 공격력 +10%)를 보여준다.
- **마우스 버튼을 놓는 순간** 유효성을 다시 확인하고 합성을 처리한다.
- 합성에 사용한 드래그 원본 아이템은 소비되고, 합성 대상 아이템은 원래 위치·회전 상태를 유지한 채 레벨이 1 상승한다.
- 서로 다른 레벨은 **합성 불가**. 동일 종류라도 Lv.1과 Lv.3은 각각 배치하거나 보상 판매 등 다른 방법으로 처리한다.
- 인벤토리에 이미 존재하는 두 아이템끼리 접촉하도록 재배치해도 자동 합성되지 않는다.

### 8.2 합성 레벨 규칙
| 대상 아이템 | 보상 아이템 | 결과 |
|---|---|---|
| 권총 Lv.1 | 권총 Lv.1 | 권총 **Lv.2** |
| 권총 Lv.2 | 권총 Lv.2 | 권총 **Lv.3** |
| 샷건 Lv.3 | 샷건 Lv.3 | 샷건 **Lv.4** |
| 탄띠 Lv.4 | 탄띠 Lv.4 | 탄띠 **Lv.5** |
| 권총 Lv.3 | 권총 Lv.1 | **합성 불가** (레벨 다름) |
| 권총 Lv.2 | 샷건 Lv.2 | **합성 불가** (종류 다름) |

**레벨 계산은 합산이 아니라 같은 레벨끼리 만나 한 단계 증가(Lv.n + Lv.n → Lv.n+1)하는 방식**이다. 합성 가능한 최대 입력 레벨은 Lv.4이고, Lv.5끼리는 합성할 수 없다.

> **성장 경로:** 보상 아이템은 기본적으로 Lv.1이며, 장착 인벤토리와 별도의 **Storage(보관 한도 5개)**에 보관한다. 이후 레벨업 정리 화면에서 보관 중인 아이템을 꺼내 동일 종류·동일 레벨 대상에 드래그하여 합성할 수 있다. 상위 레벨 아이템 보상은 없거나 매우 낮은 확률로만 제공한다. 구체 확률은 미정이다.

### 8.3 중복 보유와 합성의 관계
- 같은 종류의 무기는 **인벤토리에 최대 2개 인스턴스**를 유지할 수 있다.
- 같은 종류라도 레벨이 다르면 중복 보유가 자연스러운 선택이 된다.
- 장착된 인스턴스 각각의 공격은 독립적으로 이루어지며 Lv.3 고유 효과는 4.2절처럼 인스턴스별로 중복 적용된다.

### 8.4 좌측 Storage 보관함 (최대 5개)
- 첨부 레퍼런스 화면처럼 **인벤토리 정리 화면의 왼쪽에 세로형 Storage 패널**을 배치한다. 오른쪽에는 격자형 장착 인벤토리가 표시된다.
- Storage는 **아이템 인스턴스 개수 기준으로 최대 5개**를 보관한다. 아이템이 차지하는 격자 면적과는 별개의 수량 제한이다.
- 레벨업 정리 중에는 Storage에 **일시적으로 5개를 초과하여 담을 수 있다.** 그러나 `완료`는 **Storage 보관 수 ≤ 5**가 되어야 활성화된다.
- 5개를 초과한 상태에서는 아이템을 장착 인벤토리로 이동하거나, **동일 종류·동일 레벨 합성**, 판매, 진화 등 합법적인 정리 작업으로 개수를 줄인다. 진화가 실제로 Storage 수를 줄이는 경우에만 해소 수단으로 계산한다.
- 보관 중인 아이템은 공격, 패시브 능력치, 인접 시너지, 진화 조건의 **장착 효과를 제공하지 않는다**. 진화의 대상으로 활용하려면 적용 가능한 위치·조건을 충족해야 한다.
- 보관함의 아이템은 레벨업 정리 화면에서 장착·합성·판매에 사용한다. **Storage 내부 및 Storage↔장착 인벤토리의 드래그 합성**도 동일 종류·동일 레벨일 때 허용한다.
- 아이템 한도 초과 상태에서는 `Storage 7/5`처럼 현재 수량/한도와 경고를 표시하고, 완료 불가능 사유를 명확히 보여준다.
- **전투 중에는 Storage 정리 불가**. 다음 레벨업 정리 화면에서 재배치할 수 있다.
- `완료`를 누르기 전 장착 인벤토리의 배치·합성 등 다른 유효성도 함께 확인한다.

## 9. 레벨업 화면, 보상 및 판매

### 9.1 일시정지 및 연속 레벨업
- 경험치 보석을 수집하여 요구 경험치량을 충족하면 전투, 몬스터 행동, 생존 타이머를 일시정지하고 레벨업 효과음과 보상 UI를 재생한다.
- **한 레벨업 회차는 '후보 3개 표시 → 최대 2개 획득/판매·리롤·진화·보관 및 인벤토리 정리 → 완료'로 구성한다.**
- 한 번에 여러 레벨업 조건이 충족된 경우에도 **현재 회차의 `완료`를 누른 뒤 다음 회차 레벨업 효과음과 새 보상 UI를 다시 표시**한다. 남은 회차가 모두 처리되기 전에는 전투를 재개하지 않는다.
- 다음 회차가 시작되면 **새로운 보상 후보 3개**를 생성하고 최대 2개 획득 제한도 새로 적용한다. 이전 회차에서 판매·확정한 슬롯은 다시 열리지 않는다.
- 다중 레벨업에서 레벨업 횟수와 보상 처리 횟수가 누락되거나 중복되지 않도록 관리한다.

### 9.2 후보 3개 중 **최대 2개 획득**
- 후보로 무기·패시브·1칸 확장권·소비형 보상 등이 등장한다.
- 최대 2개까지만 획득할 수 있다. **0개 또는 1개만 획득하고 진행해도 된다.**
- 장착형 보상은 장착 인벤토리에 배치, Storage로 보관, 동일 종류·동일 레벨 아이템에 드래그 합성할 수 있다.
- **소비형 보상은 선택 즉시 적용**하고 장착 인벤토리 및 Storage에는 들어가지 않는다. 소비형 보상도 최대 2개 획득 한도에 포함한다.
- 후보 예시: **HP +30 회복**. 체력 최대치 초과 처리 및 등장 조건은 밸런스 설정 단계에서 결정한다.
- **맵 전체 경험치 보석 수집**은 추가 구현 후보. 선택 시 월드의 보석을 플레이어 중심으로 끌어와 정상 수집 절차로 처리한다. 이로 인한 연속 레벨업은 9.1의 순차 처리 규칙을 따른다.
- 인벤토리가 가득 찬 경우 기존 일반 아이템 또는 미선택 보상을 판매해 특수 재화를 얻을 수 있다.
- 장착 필수 아이템과 시작 무기도 판매할 수 있다. 필수 아이템 판매 시 탈착 효과는 §3을 따른다.

### 9.3 판매·리롤 슬롯 처리
- 레벨업 보상을 판매하면 **그 후보 슬롯은 소비되어 사라진다**.
- 특수 재화로 리롤할 때는 **아직 획득하거나 판매하지 않은 후보만** 다시 추첨한다.
- 이미 획득한 후보와 판매한 후보는 리롤 대상이 아니다.
- 모든 후보가 처리되어 리롤할 슬롯이 없다면 리롤 불가.
- 판매 금액, 리롤 비용·횟수, 동일 아이템 보상 후보 간 중복 허용 여부는 미정.

### 9.4 보상 등장 제한
- 보상 아이템은 **Lv.1 중심**이며 상위 레벨 아이템은 등장하지 않거나 매우 낮은 확률로만 등장한다.
- **무기가 진화하면 해당 종류의 일반 무기는 이후 보상 후보에 등장하지 않는다.** 진화하지 않은 Lv.5 무기의 재등장 여부는 추후 결정한다.
- 패시브 Lv.5 보상 제외 여부와 후보 부족 시 대체 보상은 추후 결정한다.

### 9.5 완료 버튼 활성화 및 실패 안내
- `완료`는 **Storage 수량이 5개 이하**이고, 장착 인벤토리에 배치 오류/미처리 드래그가 없으며, 현재 회차의 선택 상태가 유효할 때만 가능하다.
- Storage가 6개 이상이면 `완료`를 비활성화하고 **남은 정리 개수**를 표시한다. 해당 상태에서도 판매·합성·진화·아이템 이동은 가능하다.
- `완료` 후 다음 레벨업 회차가 있다면 새 회차로 진행하고, 없다면 일시정지를 해제해 전투를 재개한다.

## 10. 인벤토리 확장

| 조건 | 보상 | 상태 |
|---|---|---|
| **5분 보스 처치** | 4칸 선택 확장 | 확정 |
| **10분 보스 처치** | 4칸 선택 확장 | 확정 |
| **15분 보스 처치** | 4칸 선택 확장 | 확정 (이번 개정) |
| **일반 레벨업** | 약 **5% 확률**로 보상 후보 중 1칸 확장권 등장 | 초기 확률, 테스트 후 조정 |

- 기본 인벤토리는 **4×4**로 시작한다.
- 확장 후보는 현재 사용 가능 영역 **외곽의 상하좌우 칸**이며(4×4 기준 16칸), 플레이어가 후보 중 원하는 칸을 자유롭게 고른다. 1칸 확장권도 같은 방식이다.
- 확장 후 다음 후보는 확장된 외곽을 기준으로 다시 정한다.
- 보스 처치 시 확장과 함께 보물상자(5중 3택)를 드랍한다. (§13.1)
- 중간 보스 3회 모두 처치하면 **총 12칸 확정 확장** 가능.
- 최대 확장 가능한 형태는 별도 확정 필요. 전투 조끼의 추가 가방 보너스는 현재 **+2칸**.

## 11. 특수 재화

**획득:** 일반 보상 판매, 인벤토리 일반 아이템 판매, 일정 수 몬스터 처치 또는 조건 달성. 물리 퍼즐은 2주 이후 추가 후보.  
**소비:** 레벨업 보상 리롤, 무기 진화.  
**미정:** 판매가, 리롤 가격·횟수, 무기별 진화 비용, 처치 달성 보상 기준.

특수 재화가 부족하더라도 3중 최대 2택은 강제 구매가 아니라 획득·판매·포기·완료 선택으로 진행할 수 있어야 한다.

## 12. 몬스터 시스템과 알고리즘 실험

### 12.1 일반 몬스터
- 전투 중 무한 생성, 플레이어 추적, 공격/접촉 피해, HP, 피격, 사망.
- 처치 시 경험치 보석 드롭. 수집 절차는 §2.1을 따른다.
- 몬스터 종류 및 에셋 볼륨은 최소화.

### 12.2 직접 구현할 핵심 알고리즘
- 플레이어 추적 이동: Vector Field / Flow Field.
- 주변 검색·충돌 밀집 완화: Spatial Hash / Separation 및 필요한 수준의 Flocking.
- 내부 자료구조·갱신주기·이동 처리·샷건 넉백 통합은 개발자가 실험을 통해 결정.
- 기본 방식과 최적화 방식의 FPS, CPU 시간, GC, 주변 탐색 횟수 및 겹침 정도 비교.

## 13. 보스 출현과 공격 패턴

### 13.1 중간 보스 (5·10·15분)
| 출현 시간 | 대표 차별화 공격 | 처치 보상 |
|---|---|---|
| **05:00** | 일정 간격 **돌진** | 인벤토리 4칸 확장 + 보물상자 |
| **10:00** | 예고 후 **짧은 직선 공격** | 인벤토리 4칸 확장 + 보물상자 |
| **15:00** | **퍼지는 탄환 공격** | 인벤토리 4칸 확장 + 보물상자 |

- **보물상자:** 중간 보스 처치 시 경험치 보석 없이 상자만 드랍되며, 플레이어가 접촉하면 획득한다.
    - 획득 시 레벨업과 동일하게 일시정지하고, 레벨업 화면에 **4칸 확장 선택**이 추가된 화면에서 후보 **5개 중 최대 3개**를 획득한다.
    - 대기 중인 레벨업 회차가 있으면 레벨업을 먼저 처리한다.
    - 후보에는 소비형·확장권 등이 등장하며, **Lv.2 장비 1개가 무작위로 확정 등장**한다. 15분 보스 상자의 확정 장비를 Lv.3으로 할지는 밸런스 단계에서 결정한다.
- 보스는 일반 몬스터와 동일한 등록·이동 체계를 따른다.

- 시간대별 패턴 배정은 위 표대로 **확정**한다. (05:00 돌진 / 10:00 직선 / 15:00 확산 탄환)
- 공격별 재사용 대기시간, 피격 데미지, 체력, 이동 패턴 등 세부 파라미터는 추후 결정.
- **보스 등장에 대한 별도 UI 알림이나 카운트다운은 없음.** 보스는 맵에 자동 등장한다.
- 이전 중간 보스를 아직 처치하지 못했어도 다음 보스는 정해진 시간에 그대로 등장한다. (각 중간 보스는 5분 내에 처치되도록 밸런스로 유도)

### 13.2 최종 보스 (20분)
| 출현 시간 | 공격 패턴 | 처치 보상 |
|---|---|---|
| **20:00** | 일정 간격 **돌진** + **퍼지는 탄환 공격** (15분 보스와 발사 궤적이 다름) | 게임 클리어 |

- **20:00 자동 출현**. 처치 즉시 클리어 또는 출현 후 **90초 생존** 시 클리어.
- 15분 보스와 구분되는 구체 발사 궤적은 보스 작업 브리핑에서 결정한다.
- 최종 보스 등장 이후에도 일반 몬스터는 계속 생성된다. 처치되지 않은 중간 보스가 남아 있어도 최종 보스는 20:00에 등장한다. (§13.1과 동일 규칙)
- 2주 MVP에서는 복잡한 다단계 페이즈를 제외.

## 14. UI와 사용자 상호작용

1. **캐릭터 선택:** 시작 무기, 고정 아이템 및 특성 확인.
2. **전투 HUD:** HP, 레벨, 경험치, 생존 시간, 특수 재화. 보스 시간 안내는 생략.
3. **레벨업·가방:** **좌측 Storage(5개 한도) / 우측 장착 격자** 2영역 표시, 현재 수량(예: `7/5`)과 초과 경고, 드래그 미리보기, 회전, 배치·합성·판매·리롤·진화·확장, 조건 충족 시 `완료`.
4. **연속 레벨업:** 회차마다 레벨업 효과음과 후보 3개 UI를 재표시하고 마지막 회차 완료 후에만 전투 재개.
5. **소비형 보상:** 선택 즉시 효과를 반영하고 가방·Storage를 점유하지 않음.
6. **보물상자 보상:** 중간 보스 보물상자 접촉 시 후보 5개 중 최대 3개 획득. 4칸 확장은 외곽 후보 칸 아이콘으로 표시하고 자유 선택.
7. **진화:** 무기·패시브 Lv.5 및 인접, 재화 조건을 확인하고 진화 실행. 진화 시 가방 추가 점유 가능 여부 검사 방법은 미정.
8. **결과:** 클리어·게임 오버, 시간, 처치 수, 최종 레벨.

## 15. 데이터·시스템 경계 (AI 협업용)

- 캐릭터 데이터: 시작 무기·필수 아이템·캐릭터별 효과.
- 무기/패시브 데이터: 종류, 레벨, 효과, 대응 시너지, 진화 형태, 인벤토리 점유 도형.
- 인벤토리 영역: 장착 격자의 배치/회전/충돌/인접 판정의 **유일한 소유자**. 합성 판정 주체(인벤토리/Storage)는 인벤토리 구현 중 확정한다.
- 전투 영역: 인벤토리의 **확정된** 장착 효과를 소비하여 발사·피격·넉백 등을 처리.
- 경험치 영역: 보석 드롭 → 수집 반경 진입 → 플레이어 중심 흡수 → 도착 시 경험치 및 효과음 지급; 누적 레벨업 처리 요청.
- 보상 영역: 회차별 후보 선택·판매·리롤·최대 2개 획득, 보물상자 5중 최대 3개 획득, 소비형 즉시 적용, 미처리 레벨업 회차 관리, 진화 재화 차감.
- Storage 영역: 장착 인벤토리와 **별개로 보관**하는 목록, 임시 초과 상태 표시, **5개 이하 완료 검증**. 레벨업 정리 화면(일시정지)에서 Storage 내부 및 Storage↔장착 인벤토리 간 합성 허용.
- 웨이브/보스 영역: 게임 시간 기준 보스 생성, 처치 보상, 클리어.

> 위는 책임 경계일 뿐, 구체 클래스/메서드/배열 설계가 아니다. 개발자 담당 알고리즘 구현 방식은 강제하지 않는다. 기능 간 API/이벤트 계약은 착수 브리핑에서 승인 후 확정한다.

## 20. 최종 산출물과 개발 원칙

1. 실행 가능한 **Windows Unity 게임**과 20분 생존·진화 핵심 루프.
2. 개발자가 직접 구현하고 원리를 설명할 수 있는 **이동·공간분할·인벤토리 알고리즘**.
3. 알고리즘의 성능·장단점 실측 기록.
4. Claude Code/Codex의 작업 제안 → 승인 → 구현 → 테스트 → 리뷰 기록.
5. 구현 중 결정한 미확정 규칙을 이 기획서 및 TechSpec에 반영한 최종 리비전.
6. **Storage 5개 제한·연속 레벨업·소비형 보상의 상태 전환과 예외 상황 테스트 기록.**

**핵심 원칙: 게임 기획은 필요한 동작과 완료 조건을 정의하고, 알고리즘 설계는 개발자가 직접 탐구한다. Agent는 기획 밖 기능과 알고리즘 구현을 임의로 확대·변경하지 않는다.**
