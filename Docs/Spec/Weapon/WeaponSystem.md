## 1. 기존 문서와의 연결 및 변경점

- `GDD.md`: 플레이어는 장착 무기로 자동 공격한다. 같은 종류의 무기는 **최대 2개 인스턴스**를 장착하며, **각 인스턴스가 독립 공격**하고 Lv.3 효과도 인스턴스별 적용한다. 무기 Lv.1~5의 기본 공격력 증가, Lv.5 무기 + 대응 Lv.5 패시브의 인접 + 특수 재화로 진화한다.
- `GameFlow.md`: 레벨업/보물상자 정리 중 **몬스터 이동·공격, 투사체, 전투 타이머가 정지**해야 한다. 마지막 대기 회차를 완료하기 전 전투가 재개되면 안 된다.
- `Roadmap.md`: 무기 확장 구조 + 기본 적(4단계) → 무기 3종(6단계) → Lv.3(8단계) → 패시브(9단계) → 진화(10단계). **Flow Field·Spatial Hash·인벤토리는 개발자가 직접 구현**하고 Agent는 계약을 통해 연동한다.
- **이번 요청 우선 반영:** 미니건 진화 관통 한도 초기값 **3마리**(기존 GDD의 5마리 후보를 대체하는 *초기 구현 수치*), 권총 난사 **쿨다운 10초/지속 3초**, 샷건 방사형 **주기 4초**. 모두 인스펙터 조정 가능.
- **권총 진화 총기 수:** 기존 GDD는 진화 시 **4자루**, 이번 요청은 진화 시 난사만 명시했다. **GDD의 4자루를 유지하는 제안**으로 작성하되, 진화 시 총기 수를 인스펙터 값으로 분리한다.
- **[확정] 명칭:** 무기 명칭을 **미니건**으로 통일한다. 기존 GDD의 이전 명칭은 같은 무기를 가리킨다. 관련 문서(GDD·Combat)는 2026-11-10 동기화했다.
- **[확정] 360° 원형 감지와 비주얼 회전:** 시작 무기와 모든 추가 장착 무기는 **플레이어 중심 XZ 평면 360°**에서 각 무기의 감지 거리 내 최근접 적을 찾는다. 시작 무기만 캐릭터 모델 회전을 제어하고, 부유 무기는 각각 독립적으로 회전한다. 회전은 매우 짧고 자연스러운 **시각적 연출**이며 사격 지연·명중률 감소·디버프를 부여하지 않는다. 적이 없으면 주변 탐색을 위한 자동 회전을 하지 않는다.
- **[확정] 탄속의 상대적 차이:** 권총은 보통, 샷건은 빠름, 미니건은 느림. 실제 수치는 인스펙터에서 조절한다.
- **[확정] 샷건:** 부채꼴 내 탄환은 간격을 두고 분산 발사한다. 펠릿 수에 따른 누적 넉백에 **상한 또는 점감 효과**를 두고, 보스에도 저항 배율을 적용한다.

## 3. 공통 공격 흐름

### 3.1 시작 무기와 추가 장착 무기의 조준 책임 분리

**[확정] 소유 관계:** 현재 **주무기로 지정된 장착 무기 인스턴스 하나**만 캐릭터 모델의 시선·회전 방향을 결정한다. 시작 시에는 캐릭터의 기본 무기가 주무기이며, 이후 수동 변경하거나 판매로 자동 승계될 수 있다. 나머지 장착 무기 인스턴스는 **떠 있는 보조 무기**로 생성되어 별도로 조준한다. 무기 종류가 아닌 **장착 역할**로 구별한다. 예를 들어 카우보이가 추가로 권총을 얻더라도 그 권총은 부유 무기다.

| 항목 | 현재 주무기(직접 소지) | 기타 총기(부유) |
|---|---|---|
| 회전 제어 | 캐릭터 비주얼 + 손에 든 무기 | 해당 부유 무기의 비주얼/총구만 |
| 표적 | 해당 무기 감지 범위의 가장 가까운 적 | **해당 인스턴스** 감지 범위의 가장 가까운 적 |
| 탐색 각도 | **[확정]** 플레이어 중심 XZ 평면 360° | **[확정]** 플레이어 중심 XZ 평면 360° |
| 적 없음 | 이동 중이면 이동 방향, 정지 중이면 현재 방향 유지; 제자리 회전 없음 | 현재 방향 유지; 자동 탐색 회전 없음 |
| 발사 시점 | 유효 적 감지 및 발사 타이머 준비 시 **회전 완료 대기 없이** 발사 | 동일, 각 무기별 탄창/재장전/쿨다운 준수 |
| 사격 방향 | 발사 순간 선택한 적의 `AimPoint`로 **논리적 조준 방향**을 확정 | 동일; 독립적으로 방향 확정 |

1. **[확정] 각 인스턴스 독립 표적:** 무기 인스턴스가 자기 감지 거리 안의 살아 있고 공격 가능한 적 중 최근접 1개를 선택한다. 미니건과 샷건의 조준 표적은 서로 달라도 된다.
2. **[확정] 본체 회전 제한:** 직접 소지한 **현재 주무기의 표적만** 캐릭터 모델/손 무기 회전에 영향을 준다. 부유 무기가 적을 발견해도 캐릭터 몸통을 돌리지 않는다.
3. **[확정] 후방 적 감지:** 시작 무기와 부유 무기는 모두 후방 적도 감지 거리 안에 있으면 감지한다. 적이 하나도 감지되지 않을 때만 탐색용 제자리 회전을 하지 않는다.
4. **[확정] 발사와 회전 분리:** 표적 탐지 직후 조준 방향과 짧은 회전 연출을 시작한다. 무기별 발사 타이머·탄약 등 기존 조건이 준비되어 있으면 회전 완료를 기다리지 않고 사격한다. `aimTolerance`·추가 조준 대기·회전 중 명중률 감소를 적용하지 않는다.
5. **[확정] 비유도:** 발사 순간 대상 위치를 샘플링하고 탄환은 고정 방향으로 전진한다. 표적이 움직이면 빗나갈 수 있다.
6. **[확정] 거리 비교:** 탐색 원점은 플레이어 루트 XZ 위치로 통일한다. 가장 가까운 적의 거리를 해당 중심으로 비교한다. 방향은 해당 무기 `Muzzle`→`AimPoint`로 계산한다.
7. **[확정] 논리 조준/비주얼 회전 분리:** 탄환 발사 방향은 발사 순간 표적 위치로 바로 산출하고, 캐릭터 몸통은 짧은 시간 동안 자연스럽게 회전한다. **[설계 제안]** 총구와 탄환 방향이 시각적으로 크게 어긋나지 않도록 손 무기·부유 무기에 별도 조준 피벗(또는 발사 순간 정렬 연출)을 둔다. 이는 게임플레이 페널티가 아닌 표현상의 문제다.
8. **[확정] 반경 경계·동일 거리 우선순위:** 플레이어 루트와의 XZ 거리가 탐지 반경과 같은 적은 감지 대상에 포함한다. 거리가 같은 표적이 여럿이면 생성 순 ID(`SpawnId`)가 낮은(먼저 생성된) 적을 선택하며, 후보 목록의 순서와 무관하다.

**[설계 제안] 구조:** 이동에는 기존 `CharacterController.SimpleMove`를 유지하고, 시작 무기가 목표를 선정하면 `PlayerVisualRoot`를 `Quaternion.RotateTowards` 등으로 **짧은 시간** 부드럽게 회전시킨다. 부유 무기는 각자 `FloatingWeaponPivot`과 `Muzzle`을 소유해 독립 회전한다. 떠 있는 위치 오프셋은 플레이어를 따라 이동시키되 조준 방향과 분리한다. 회전 속도·보간 시간은 인스펙터에서 연출용으로 조절한다.

**[확정] 감지 정책:** 시작 무기와 부유 무기는 모두 **플레이어 중심 360° 원형 범위**에서 탐색한다. 부채꼴은 샷건 산탄·미니건 탄퍼짐 등 **발사 패턴**에만 사용하며 표적 감지의 각도 제한으로 사용하지 않는다.

**[확정] 증설·Lv.3/진화:** 주무기 인스턴스의 총기 중 **1자루만 직접 소지**하고 나머지는 모두 부유 총기로 배치한다. 다른 장착 인스턴스의 모든 총기도 부유한다. 권총 Lv.3은 한 인스턴스에서 2자루, 진화 권총은 기존 GDD 기준 4자루를 사용한다. 전체 **총기 수에 따라 360° 균등 배치**하며 각 총기는 소속 인스턴스의 공격 상태를 공유하되 시각적 조준은 독립 가능하다. 상세 규칙은 §3.4·§3.5 참조.

### 3.2 감지 범위와 투사체 비행 거리 구분

- **DetectionAngle:** 모든 무기에 **360° 고정**(시야각으로 표적을 제한하지 않음). 별도 시야각 설정은 필요하지 않다.
- **DetectionRange:** **플레이어 루트 중심**에서 각 무기별로 적용하는 360° 원형 탐색 반경. 탄환 최대 비행 거리와는 별개다.
- **ProjectileMaxDistance / Lifetime:** 투사체 이동을 종료하는 한계. 샷건은 짧고 권총·미니건은 충분히 길게 설정한다.
- **CameraVisibleArea:** 권총·미니건의 *유효 피격 영역*. 탄이 월드에 존재할 수 있더라도 화면 밖에서는 더 이상 게임에 영향을 주지 않는다.
- **[확정]** 표적 탐색에 카메라 화면 경계나 플레이어 전방 각도를 조건으로 사용하지 않는다. **모든 무기는 플레이어 중심 거리로 탐색**하며, 권총·미니건 투사체의 화면 밖 피해 무효화는 **발사 이후 탄환 처리**에만 적용한다.

### 3.3 3D 탑다운 조준·탄환 평면

- XZ 평면에서 방향 계산: `Vector3.ProjectOnPlane(targetAimPoint - muzzle.position, Vector3.up).normalized`.
- 투사체의 높이는 발사 총구의 Y에서 유지하는 방식을 우선 제안한다. 3D 콜라이더에 대한 실제 적중을 안정화하려면 적의 *탄환 피격 Collider*가 그 높이를 가로지르는지 검증한다.
- 직접 소지 무기에 의한 캐릭터 회전은 루트 이동·CharacterController와 충돌하지 않는 `VisualRoot` 또는 모델 회전에만 적용한다. 부유 무기 회전은 독립 피벗에 적용한다. 이동은 `CharacterController.SimpleMove`(Roadmap 확정)로 유지한다.
- **[설계 제안]** 직접 든 총기는 손의 `Muzzle`을, 부유 총기는 배치 슬롯의 `Muzzle`을 사용한다. 각 슬롯의 위치/조준 방향을 분리하고, 발사 순간 논리 조준 방향은 해당 총구에서 적 `AimPoint`를 향해 계산한다.

### 3.4 총기 수와 플레이어 중심 원형 배치

**[확정]** 인벤토리의 **무기 인스턴스 수**와 월드에 표시되는 **총기(총구) 수**를 구분한다. 같은 종류 무기는 인벤토리에 최대 2개 *인스턴스*까지 장착 가능하며, 권총의 Lv.3/진화로 늘어난 자루는 새 아이템/장착 인스턴스가 아니다.

- 기본 규칙: **현재 주무기의 손에 든 총기 1자루를 0° 기준**으로 삼아 플레이어 주변에 총기 수 `N`만큼 배치한다. 슬롯 번호 `i=0..N-1`의 각도는 `i × (360° / N)`이다. 슬롯 0은 손에 든 총기이고, 나머지 `N-1`개는 부유 총기다.
- 예시: 2자루 → `0°, 180°` / 3자루 → `0°, 120°, 240°` / 4자루 → `0°, 90°, 180°, 270°`.
- `0°`는 **현재 캐릭터의 바라보는 방향에 따른 로컬 기준**이다. 캐릭터의 방향이 바뀌면 슬롯 배치도 같이 회전하지만, 부유 총기의 **총구 조준 회전은 각각 독립적**이다.
- 모든 총기의 **표적 감지 원점은 플레이어 중심**이며, 탄환 방향은 발사하는 **각 총기의 Muzzle**에서 대상 `AimPoint`로 산출한다.
- 원형 배치에서 손 무기의 위치가 중심 가까이 있고 부유 무기와 정확히 같은 원 궤도에 있지 않을 수 있다. **논리적 0° 기준점**과 실제 손 무기의 3D 좌표는 구분하며, 부유 슬롯만 플레이어 중심 원 궤도에 배치한다.
- 권총 한 인스턴스의 두 자루가 같은 발사 타이머와 같은 대상 스냅샷을 공유할지, 총기마다 다른 표적을 고를지는 **[결정 필요]**. MVP 제안은 **인스턴스 단위로 표적 하나와 타이머 하나를 공유**하고 두 총구에서 발사하며, 다른 인스턴스는 독립 탐색한다.
- 총기가 증가·감소하면 기존 총기 뷰를 가능한 재사용하며 배치 각도만 갱신한다. 풀링과 시각적 위치 보간을 활용하고 매번 전부 파괴/재생성하지 않는다.
- 총기가 많아 충돌하거나 서로 겹치면 원형 배치 반경을 늘리고, 필요할 때만 2중 원형 배치를 도입한다. **총기 수 상한·2중 원 전환 기준은 미정**으로 남긴다. 임의의 상한을 확정하지 않는다.

### 3.5 주무기 선택·판매·합성·진화 및 승계

**[확정]** 시작 무기 또한 판매 가능하며, **주무기는 장착된 무기 중 플레이어가 인벤토리 UI에서 직접 지정할 수 있다.** 별도의 주무기 지정이 없다면 시작 장비를 유지한다.

1. **지정 유지:** 현재 주무기가 장착 상태로 존재하면 레벨이 더 높은 장비를 얻거나 다른 장비가 진화해도 자동 변경하지 않는다.
2. **자동 승계:** 현재 주무기를 판매하거나 장착 해제하여 더 이상 전투 장착 무기가 아니면 남은 장착 무기에서 **진화 → 고유 무기 → 최고 레벨 → 인스턴스 ID(먼저 장착)** 순서로 새 주무기를 지정한다. 진화 우선은 권장 확정 정책이며, 인벤토리 UI 수동 지정이 언제나 우선한다.
3. **합성:** GDD의 동일 종류·동일 레벨 합성에서 대상 인스턴스가 유지되면 그 인스턴스의 주무기 역할도 유지한다. 소멸하는 드래그 원본이 주무기였다면 자동 승계 규칙을 적용한다.
4. **진화:** 진화 자체는 주무기를 강제로 바꾸지 않는다. 진화한 주무기는 역할을 유지하고, 증가한 총기 수만큼 배치 슬롯을 다시 계산한다.
5. **맨손 상태:** 전투 장착 무기가 0개라면 주무기 없음, 자동사격 중지, 캐릭터 회전은 표적 없음과 같이 이동 중이면 이동 방향, 정지 중이면 현재 방향 유지(제자리 회전 없음). 이후 장착이 생기면 첫 장착 무기를 주무기로 지정한다.
6. **인벤토리 정리 중:** 주무기 지정·판매·장착/해제·진화 등은 레벨업/보물상자 정리 화면에서 처리한다. `완료` 후 장착 결과를 전투 시스템에 확정 반영한다. Storage에 든 무기는 주무기로 지정할 수 없다.

**[설계 제안]** `PrimaryWeaponInstanceId`와 장착 순번을 무기 인스턴스 ID로 관리하고, `PrimaryWeaponChanged` 이벤트로 캐릭터 손 무기 뷰·원형 슬롯·HUD를 갱신한다. 주무기 승계는 **무기 외형 및 몸통 회전 책임**만 바꾸며, 모든 장착 인스턴스의 무기별 독립 발사와 레벨·시너지 효과는 유지된다.

### 3.6 캐릭터 고유 아이템 탈착·판매 — 위험/보상 선택

**[확정]** 캐릭터 고유 아이템(카우보이 모자, 전투 조끼, 헤비거너의 고유 1×1 아이템)은 **탈착 및 판매가 가능**하다. 탈착 상태에서는 작은 보상성 버프를 얻는 대신 **더 크고 명확한 디버프**를 받는다. 고유 아이템을 보관함(Storage)에 넣는 것도 탈착이며, 다시 장착하면 탈착 효과를 해제하고 원래 고유 아이템 효과를 복원한다. 판매한 경우 해당 아이템을 재획득하지 않는 한 탈착 상태가 지속된다.

- **[확정] 버프보다 디버프 우위:** 버프와 디버프가 단순히 상쇄되어 탈착이 언제나 이득이 되지 않도록 한다. 아래 수치는 **초기 밸런스 제안**이며 최종 확정 수치는 플레이 테스트 후 조절한다.
- **[확정] 시작 무기 판매와 독립:** 시작 무기를 판매했다는 이유로 별도의 캐릭터 고유 아이템 탈착 페널티를 부여하지 않는다. 고유 아이템 상태만으로 효과를 판단한다.
- **[확정] 효과 처리:** 인벤토리 `완료` 시 캐릭터 고유 아이템이 장착 격자에 유효 배치되었는지 판정하여 `Equipped` 또는 `Unequipped` 상태를 갱신한다. 중복 디버프 적용 금지, 재장착 시 완전 복구.

| 캐릭터/고유 아이템 | 고유 아이템 탈착 시 디버프(주효과) | 탈착 시 버프(보조효과) | 초기 평가 |
|---|---|---|---|
| **카우보이 / 카우보이 모자** | **권총 정확도 대폭 감소:** 정확한 직선 조준 대신 발사 방향에 **랜덤 탄퍼짐** 적용. 예시 `±15°`(전체 30°), 권총 특유의 정밀 사격 상실 | 권총 발사 간격 **10% 감소** 예시: 1.5초 → 1.35초 | 난사로 연사감이 생기지만 중·원거리 명중률이 눈에 띄게 악화되도록 설계 |
| **겁쟁이 생존자 / 전투 조끼** | **받는 피해 +30%**(예시), **전투 조끼가 제공하는 인벤토리 +2칸 보너스 비활성화** | 이동속도 **+5%**(예시) | 방어/공간 손실이 작은 기동성 증가보다 명확히 크게 작용하도록 설계 |
| **헤비거너 / 고유 1×1 아이템(종류 미확정)** | **미니건 탄퍼짐 각도 +40%**(예시; 정확도 크게 악화), 재장전 시간 **+20%**(예시) | 이동속도 **+5%**(예시) | 장거리 화력과 지속 사격의 손실이 작은 이동 보너스보다 크게 작용하도록 설계 |

**주의 — 수치와 판정 분리:** 위 예시가 모든 상황에서 정량적으로 '버프보다 큰 손해'를 보장하는 것은 아니므로, 전투 지표(명중률·초당 유효 피해량·사망률)를 측정해 검증해야 한다. 특히 적이 가까운 경우 카우보이 탄퍼짐의 손해가 줄어들 수 있으므로, 필요하면 추가적인 권총 피해 감소 등 **디버프 보강안을 별도 승인**받는다.

#### 전투 조끼 +2칸 회수 시 예외 처리

기존 GDD는 전투 조끼 착용으로 인벤토리 확장 +2칸을 제공한다. **[설계 제안]** 탈착 또는 판매 시 그 **2칸을 사용 불가로 되돌리는 정책**을 택하되, 회수 대상 칸에 다른 아이템이 배치되어 있다면 **탈착/판매를 확정하지 않고 정리 UI에서 재배치하도록 안내**한다. 이미 획득한 보스/레벨업 확장 칸은 회수하지 않는다. 회수할 칸 식별·격자 유효성 판단은 개발자 담당 `Inventory.md` 계약을 통해 결정하며, Agent가 직접 격자 내부 로직을 변경하지 않는다.

#### 효과의 적용 범위와 우선순위

- 캐릭터 고유 아이템 탈착 효과는 **장착한 무기 인스턴스 중 해당 무기 종류**에 적용(권총·미니건). 이동속도 및 받는 피해 효과는 캐릭터 전역에 적용한다. **[결정 필요]** 무기별 패시브/진화와 중첩 시 최종 수치 계산 순서와 하한/상한.
- **[설계 제안]** 카우보이의 권총 공격력 +10% 캐릭터 고유 특성은 유지하되, 모자 탈착 상태의 추가 랜덤 탄퍼짐을 별도로 합성한다. 즉, 모자를 팔았다고 캐릭터의 기본 정체성까지 제거하지는 않는다.
- UI에 고유 아이템 장착/탈착 효과의 **수치 및 위험 경고**를 표시한다. 재장착한 경우 탈착 효과가 자동 취소됨을 보여준다.

## 4. 화면 밖 투사체 무효화 — 중요 계약

**[확정]** 권총과 미니건 탄환은 Game View 카메라 화면 바깥으로 나간 후 적을 맞혀도 피해를 주거나 기타 전투 효과를 발생시켜서는 안 된다. 권장 구현은 **카메라 경계에서 즉시 비활성화/풀 반환**이다.

1. **[설계 제안]** 실제 플레이 카메라(`Camera`/CinemachineBrain이 구동하는 출력 카메라) 기준으로 투사체 위치를 `WorldToViewportPoint`로 투영한다.
2. `viewport.z > 0`, `0 <= viewport.x <= 1`, `0 <= viewport.y <= 1` 범위인지 판별한다. 범위 밖이면 **즉시 `Despawn`** 처리한다. UI 패널·화면 장식이 차지하는 영역은 자동으로 제외되지 않으며, 이는 *카메라의 렌더 화면 경계*를 의미한다.
3. **충돌 처리 직전에도 가시 영역 검사**를 다시 실행해, 프레임/물리 스텝 사이에 화면 밖 적중이 처리되는 상황을 막는다. 밖이면 **피해·넉백·관통 카운트·적중 이펙트 모두 취소**한다.
4. **[설계 제안]** 발사 직후 총구가 화면 안에 있음을 확인한다. 화면 밖 총구에서 생성된 탄이 화면 안으로 들어오는 특수 상황은 MVP에서는 바로 비활성화한다.
5. 화면 안에서 적중 후 전투 처리가 일어나는 도중 다음 프레임에 화면 밖으로 나간 것은 이미 일어난 적중을 되돌리지 않는다. 정확한 경계 교차 시점까지 요구한다면 *투사체 이동 경로에 대한 뷰포트 교차 판정*을 별도 확장한다.

**주의: `Renderer.isVisible`을 단독 사용하지 않는다.** 에디터 Scene 뷰 카메라에도 영향을 받고, 렌더링 바운드가 아닌 투사체의 *피격 기준 위치*와 다를 수 있다. `OnBecameInvisible`도 게임 로직의 유일한 판정 수단으로 사용하지 않는다.

**경계 케이스:** Cinemachine 추적 중 카메라가 움직여 탄환이 화면 밖으로 나갈 수 있다. 이 경우에도 화면 밖이면 제거한다. 화면 비율·해상도 변경 후에도 뷰포트 판정은 유지된다. 카메라 사각형 가장자리에 걸친 탄환은 **탄환 중심점 기준**으로 판단하는 것을 MVP 정책으로 제안한다.

> **추가 안전장치:** 샷건은 짧은 이동 거리로, 권총·미니건은 카메라 경계와 별도로 `MaxLifetime` 또는 `MaxDistance`를 둬 풀 미반환을 방지한다.

## 5. 무기별 세부 설계

### 5.1 권총 (`Pistol`)

**[확정]** 긴 감지 반경에서 가장 가까운 적의 **사격 순간 기준 위치**를 향해 1.5초마다 발사한다. 재장전·유도 없음. 보통 탄속으로 진행하므로 적 이동 시 빗나갈 수 있으며, 탄은 원거리 진행 중 화면을 나가면 효과 없이 제거된다.

- **기본:** 탄환 1개/총구/발사 이벤트. `fireInterval = 1.5f` (인스펙터 조절). 발사 간격은 실제 발사 성공 시점 기준으로 운영하는 것을 제안한다.
- **Lv.3:** 해당 *권총 무기 인스턴스*의 총구/총기 수가 `2`가 된다. 두 총구에서 같은 표적 스냅샷을 향해 거의 동시에 발사한다(**[결정 필요]** 교대 발사 vs 동시 발사; MVP는 동시 발사).
- **진화:** 기존 GDD의 권총 `4`자루를 유지하는 안. 기본 사격과 별도로 **난사 상태(Burst)**를 추가한다. `burstCooldown = 10f`, `burstDuration = 3f` 모두 조절 가능.
- **[설계 제안]** 난사 동안 `burstFireInterval`로 빠르게 연속 발사하고, 일반 발사는 **난사에 대체**된다. 난사 종료 후 일반 사격 타이머를 재시작한다(중복 발사 폭증 방지). 최초 난사 시작은 진화 후 10초 경과 시점으로 한다.
- **[결정 필요]** 난사 탄속, 탄퍼짐, 초당 발사량 및 난사 쿨다운 계산 기준(시작~시작 또는 종료~다음 시작). **제안:** *난사 종료 후 10초 대기*를 `burstCooldown` 의미로 고정해 명확히 한다.
- 난사 도중 표적이 사망하면 매 난사 발사 시점마다 최신 유효 표적을 다시 찾는다. 표적이 없으면 해당 샷을 생략하되 난사 지속 시간은 흐른다.

**검증:** 정지한 적은 탄이 향하고, 움직이는 적은 빗나갈 수 있음 / Lv.3에서 한 무기 인스턴스만 2자루 / 진화 난사 중 일시정지 시 발사·쿨다운 정지.

### 5.2 샷건 (`Shotgun`)

**[확정]** 짧은 범위 내 가장 가까운 적을 기준으로 부채꼴 산탄을 2.5초마다 발사한다. 탄은 짧은 거리에서 제거된다. Lv.3 적중 시 넉백. 진화 시 일반 산탄의 범위·반경이 증가하며 4초마다 360° 방사형 발사가 추가된다.

- **기본:** 발사 이벤트 1회에 `pelletCount`발을 부채꼴 `spreadAngleDegrees` 안의 여러 방향으로 발사. **[확정]** 펠릿은 부채꼴 안에서 **일정 각도 간격**을 두고 발사한다. **[설계 제안]** `pelletCount > 1`이면 양 끝 각도를 포함해 균등 분포시키고, 1발이면 중앙으로 발사한다. 랜덤 지터는 기본 적용하지 않는다.
- `fireInterval = 2.5f`, `projectileMaxDistance`를 짧게 설정(둘 다 인스펙터). `pelletSpeed`, `pelletCount`, `spreadAngleDegrees`는 실험값.
- **[설계 제안]** 동일 샷건의 **한 번의 발사 이벤트에서 같은 적에 여러 펠릿 적중 시** 각각 피해를 줄지, 적 1회만 처리할지 옵션을 둔다. *초기 권장:* 각 펠릿이 개별 피해를 주되 관통 없이 첫 적에 닿으면 반환한다. 이에 따른 근접 화력 폭증을 밸런스 테스트한다.
- **Lv.3:** 산탄 적중 시 `KnockbackRequest(direction, strength, duration)`와 같은 의미상 계약으로 넉백 요청. **실제 몬스터 이동 합성·우선순위는 개발자 담당 이동 시스템에서 결정**하고 무기 코드가 Flow Field/Separation 상태를 직접 변경하지 않는다.
- **진화:** `evolvedSpreadAngle`, `evolvedMaxDistance` 등으로 기본 공격의 퍼짐 범위와 유효 이동 반경을 증가시킨다. 별도로 `radialInterval = 4f`마다 `radialProjectileCount`개의 탄을 **XZ 평면 360° 균등 각도**로 방사한다.
- **[설계 제안]** 360° 방사는 일반 발사 타이머와 독립된 스킬로 처리하며 주변에 유효 적이 없더라도 주기 도달 시 발사한다. `radialOnEvolveImmediately` 등 첫 발동 옵션은 추후 선택. 방사탄에 Lv.3 넉백을 적용할지 여부는 **[결정 필요]**(기본 제안은 적용).

**검증:** 근접 대상 다수 펠릿 적중 / 최대 거리에서 소멸 / Lv.3 넉백이 이동 알고리즘과 충돌하지 않음 / 진화 후 360° 발사가 플레이어 이동 방향과 무관하게 전 방향 균등.

### 5.3 미니건 (`Minigun`, 코드 명칭은 협의)

**[확정]** 권총보다 약간 긴 감지 반경에서 가장 가까운 적 방향을 중심으로 **좁은 부채꼴 안에서 매 탄 랜덤 각도**로 연사한다. 사격 시 표적 위치에 유도되지 않으며 원거리에서 빗나갈 수 있다. 화면 밖으로 나간 탄은 무효. **100발 소진 후 5초 재장전**(조절 가능).

- `magazineCapacity = 100`, `reloadDuration = 5f` (인스펙터), `shotsPerSecond` 또는 `fireInterval` 중 **한 가지 기준만** 내부 정식 데이터로 사용한다. 초당 발사 수는 미정.
- **[설계 제안]** 누르고 있는 트리거가 없는 자동사격이므로 표적이 없으면 **탄약을 소비하지 않고** 남은 탄약과 재장전 진행을 유지한다. *탄창 0발이 되는 즉시* 재장전을 시작하며, 표적 유무와 무관하게 전투 시간에 따라 완료한다.
- **[설계 제안]** 매 발사에서 `yawOffset = Random.Range(-spread/2, +spread/2)`로 XZ 방향을 결정. 지나친 `Random` 호출/프레임 중복 탐색을 줄이려면 타이머 기준 발사 시에만 계산한다.
- **Lv.3:** `spreadAngleDegrees`를 `level3SpreadAngle` 또는 `accuracyMultiplier`로 축소한다(감지 거리나 타격 판정 크기를 늘리는 방식이 아님).
- **헤비거너 고유 특성:** GDD에 정확도 +10%가 정의만 되어 있으므로, **[설계 제안]** 현재 탄퍼짐 각도에 0.9배 적용. **냉각기** 인접 시너지(각도 감소)와 함께 적용 시 어떤 순서로 계산하든 일관되게 *기본각 × Lv.3 계수 × 캐릭터 계수 × 인접 패시브 계수*로 합성한다. 최종 하한각은 추후 밸런스 결정.
- **진화:** `maxUniqueTargetsHit = 3` 초기값(인스펙터 변경 가능). **한 탄환이 최대 3개의 서로 다른 적에게 피해**를 준다는 의미로 제안한다. 동일 적 Collider가 여러 개이거나 한 물리 스텝에 중복 접촉하더라도 **동일 적은 1회만** 카운트/피해를 처리한다. 세 번째 서로 다른 적에게 피해를 준 직후 풀 반환한다.
- **[확정]** 진화 시 **탄환 수 증가**도 포함한다. 증가 방식(발사당 추가 탄환/연사속도 증가)은 **[결정 필요]**로 남기며, `evolvedProjectilesPerShot` 등을 별도 설정값으로 둔다. 현재 문서의 `1발` 초기안은 증가 효과를 표현하지 못하므로 확정 초기값으로 쓰지 않는다.
- **추후 UI:** 전투 HUD 좌하단 또는 우하단에 미니건 탄약 `현재/최대` + 재장전 남은 시간/진행 상태. **현재 무기 구현 단계에서 UI를 반드시 만들지 않으며**, UI가 구독할 `AmmoChanged`, `ReloadStarted`, `ReloadFinished` 등의 읽기 전용 이벤트 계약을 준비한다.

**검증:** 100발을 발사하면 추가 발사 없이 5초 장전 / 사격 중 타깃 사라지면 탄 감소 중단 / Lv.3 분산각 감소 / 진화 관통은 같은 적 중복을 제외한 3마리 한도 / 화면 밖 이동 시 관통·피해 모두 중단.

|---|---|---|
| `WeaponTargeting` | 무기 인스턴스별 시야·감지 거리·최근접 유효 적 조회 | Spatial Hash 사용 여부는 개발자와 **인터페이스만 협의** |
| `PlayerAimController` | **직접 소지한 주무기 표적만** 받아 플레이어 비주얼을 부드럽게 회전 | CharacterController 이동 코드와 분리 |

| `Damageable`/`IDamageable` | 피해 수신, HP 감소·사망 | 진화 관통의 동일 적 식별 필요 |

### 6.2 공통 데이터 항목(개념적 필드)

```text
WeaponDefinition (ScriptableObject, 공유 설정)
  weaponType                     Pistol / Shotgun / Minigun
  detectionRange                 탐지 거리
  detectionAngle                 모든 무기 360° 고정(별도 인스펙터 설정 불필요)
  (turnSpeedDegreesPerSecond     무기 SO가 아닌 PlayerAimController._turnSpeed에 둠, 플레이어 비주얼 회전속도)
  fireInterval                   기본 발사 간격 (미니건도 단일 단위로 환산)
  projectileSpeed                탄속
  projectileMaxDistance          최대 비행 거리
  projectileMaxLifetime          최대 생존 시간
  projectileDamage               기본 피해 (레벨·시너지 합성 전)
  disableOutsideGameCamera       권총/미니건 true
  ... weapon-specific settings   pelletCount, coneAngle, magazineCapacity 등

WeaponInstance (장착별 런타임 데이터)
  instanceId / itemId / level / isEvolved
  mountRole                      HeldPrimaryWeapon / FloatingWeapon (주무기 역할은 변경 가능)
  nextShotTimer / evolutionSkillTimer
  currentAmmo / isReloading / reloadTimer  (미니건)
  resolvedStats                  배치 시너지 등을 적용한 읽기용 스냅샷

ProjectileSpawnContext (풀에서 꺼낼 때 매번 초기화)
  owner / weaponInstanceId / damage / direction / spawnPosition
  speed / maxDistance / maxLifetime / requireCameraVisibility
  knockbackData / maxUniqueTargetsHit / shotId
```

- **[설계 제안]** 기본 설정 노출은 `[SerializeField] private` 또는 ScriptableObject의 직렬화 필드로 하되, 외부에는 읽기 전용 프로퍼티·이벤트를 제공한다.
- **[설계 제안]** 공격력·공속·정확도 시너지는 보상/인벤토리 `완료` 후 전투 재개 직전에 **한 번 재계산**하고, 매 탄 발사 시 아이템 격자를 다시 스캔하지 않는다.
- `Update()`를 무기/총구/투사체마다 무조건 추가하는 설계는 피한다. **[설계 제안]** 장착 무기별 발사 타이머는 플레이어 전투 루프에서 관리하고, 투사체는 필요 시 통합 업데이트·풀·배치 처리로 최적화한다. 초기에 단순한 개별 `Update`를 써도 **Profiler로 측정한 뒤** 변경한다.
- 진화 탄환 다량 생성 시 풀 용량을 실측 기준으로 늘리고, 소진 시 대응(확장/건너뛰기)을 별도 정책으로 둔다.

### 6.3 공통 발사 절차(의사코드)

```text
CombatTick(deltaTime):
  if GameState != Combat: return
  for each equipped WeaponInstance independently:
    update weapon timers and reload/evolution states
    if a normal shot is due and weapon can fire:
       target = FindNearestEnemyInPlayerCenteredRadius(weapon.detectionRange)
       if target is valid:  // 회전 완료 대기 없이 발사
          if weapon.mountRole == HeldPrimaryWeapon: RequestSmoothBodyRotation(target)
          else: RequestIndependentWeaponVisualAim(weapon, target)
          aimDirection = SnapshotDirectionFromMuzzleTo(target.AimPoint)
          FirePattern(weapon, aimDirection)
          CommitAmmoAndCooldown(weapon)
    if evolved skill is due:
       ActivateSkillByWeaponType(weapon)

ProjectileTick(deltaTime):
  for each active projectile:
    move along fixed direction
    if camera-culling enabled AND outside output camera viewport: Despawn
    else if max distance/lifetime exceeded: Despawn

OnProjectileContact(enemy):
  if projectile inactive OR enemy invalid: return
  if camera-culling enabled AND outside output camera viewport: Despawn; return
  if enemy already hit by this projectile: return
  apply damage (and eligible knockback)
  record unique enemy hit
  if unique hit limit reached: Despawn
```

위 순서는 **계약 설명을 위한 의사코드**다. FixedUpdate/Rigidbody/Trigger/Raycast 등 실제 물리 구현은 적 충돌체와 기존 이동 구조를 확인한 뒤 결정한다.

## 7. 충돌·피격·관통의 정확성

- **충돌 누락 방지:** 빠른 미니건 탄은 프레임 사이 적을 통과할 수 있다. **[설계 제안]** 이동 전후 구간의 `Raycast`/`SphereCast` 등 *연속 구간 검사*를 고려한다. `OnTriggerEnter` 하나만으로 고속 탄을 보장하지 않는다.
- **전투 영역:** 투사체 피격은 월드 XZ 방향 기준이며, 필요 시 얇은 SphereCast로 모델 중심과 실제 Collider의 높이 차이를 보정한다.
- **피해 대상:** 적 루트 또는 별도 `EnemyId` 기준의 고유 식별자를 사용한다. 미니건 관통은 `HashSet`/작은 고정 배열 등으로 탄환마다 *이번 탄이 이미 맞힌 적*을 기록하고 풀에서 다시 꺼낼 때 비운다.
- **샷건:** 각 펠릿은 별개 투사체(및 피해 이벤트). 한 적의 복수 펠릿 적중 허용 여부는 5.2의 제안 정책을 따른다.
- **화면 경계 우선:** 권총·미니건은 충돌 시 *적중 처리 전에* 카메라 뷰포트 체크. 밖이면 피해·넉백·관통 카운트·처치·경험치 획득까지 발생하지 않는다.
- **투사체 안전성:** 하나의 투사체에 중복 `Despawn`/중복 피해가 발생하지 않도록 활성 상태 및 `shotId`를 체크한다.
- **아군/자기 자신:** 플레이어 탄환은 플레이어를 피격하지 않도록 레이어 또는 충돌 필터 적용.

## 8. 넉백·몬스터 이동 알고리즘 간 계약

GDD/Roadmap에서 Flow Field·Spatial Hash·Separation과 넉백의 결합은 **개발자 담당 알고리즘 영역**이다. Agent는 이동 벡터·상태 우선순위를 직접 변경하지 않고, 계약에 따라 넉백 요청만 전달한다.

- **[확정] 샷건 다중 적중 의도:** 같은 발사에서 한 적이 맞은 펠릿 수가 증가하면 넉백도 증가한다. 과도한 밀림은 **최대 상한을 두거나, 추가 적중의 증가폭을 점차 줄이는 방식**으로 제어한다. **[설계 제안]** 두 장치를 함께 적용할 수도 있다.
- **[확정] 보스:** 보스에게도 넉백을 적용하되 **넉백 저항 배율**을 둔다. 실제 저항 수치는 미정이다.
- **[설계 제안] 요청 정보:** `shotId`, 피격 대상 ID, 발사 방향, 동일 발사에서 적중한 펠릿 수, 기본 넉백 세기, 보스 저항값 등을 이동 시스템에 전달한다. 샷건의 각 펠릿 피해 처리는 별도로 유지할 수 있다.
- **[설계 제안] 점감형 누적 예시:** 1발 적중 시 1.0m, 2발 1.5m, 3발 1.75m처럼 **증가폭이 절반씩 감소**하는 방식이다. 이는 이해를 위한 예시이며 **실제 월드 이동 거리나 물리 공식으로 확정하지 않는다**. 실제 이동에는 누적 넉백 세기와 몬스터 이동 시스템의 시간·감쇠 규칙을 사용한다.
- **[결정 필요] 중첩 기준:** 같은 `shotId`로 한 적에게 적중한 펠릿 수를 모아 **한 번의 집계 넉백**을 적용할지, 펠릿 도착마다 누적량을 갱신할지 선택한다. 집계 방식은 프레임 순서에 덜 민감하지만, 펠릿 도착 시간이 다르면 집계 종료 기준이 필요하다.
- **[결정 필요] 상한/점감 선택과 보스 저항 적용 순서:** 상한만 적용할지, 점감만 적용할지, 둘 다 적용할지 선택한다. 두 장치를 함께 사용할 때 초기 제안은 **점감 누적 → 상한 → 보스 저항 배율**이다.

**주의:** 실제 피격에 의한 피해량, 넉백 이동 거리, 관성/외력은 서로 다른 개념이다. `KnockbackRequest`는 이동 담당 시스템과 API를 합의한 다음 구체화한다.

## 9. 일시정지, 스킬 타이머, 인벤토리 연동

1. 레벨업 또는 보물상자 UI가 열리면 **일반 발사, 탄 이동, 피해, 재장전, 난사/360도 스킬 지속·쿨다운, 탐색으로 인한 회전** 모두 중단한다.
2. 게임 진행 시스템이 전투 시간의 유일한 소유자다. **[설계 제안]** 무기 타이머는 전투 중 전달된 `deltaTime`만 더하고, UI를 위해 `unscaledDeltaTime`을 사용하지 않는다.
3. 중간 보상 완료 후 다음 레벨업이 남았다면 계속 정지한다. 마지막 회차 완료 후에만 발사 루프 재개.
4. 인벤토리에서 무기 레벨/진화/장착 또는 인접 효과가 바뀌어도 *정리 UI 중에는 새 투사체가 발생하지 않으며*, `완료` 시 확정한 `ResolvedStats`를 적용한다.
5. 같은 무기 2개 장착 시 타이머·잔탄·진화 스킬을 **각 인스턴스별로 유지**. 판매·합성으로 사라진 무기의 타이머/이벤트를 해제하고, 합성 대상은 원래 인스턴스를 유지하면서 레벨 변화만 반영한다(GDD §8).
6. **[결정 필요]** 레벨 상승에 따른 남은 쿨다운 리셋 여부: **제안** 기존 남은 타이머 유지, 새로운 수치만 적용. 진화로 *새 스킬*이 생긴 경우 첫 스킬 쿨다운부터 시작.
7. 미니건 탄약 UI는 추후 연결하며, UI는 무기 데이터를 직접 수정하지 않고 이벤트/읽기 전용 상태만 관찰한다.

## 12. 기능 테스트 체크리스트

- [ ] 권총 Lv.3으로 총기 2자루가 되면 손 무기를 0°로 하여 다른 총기가 180°에 부유한다.
- [ ] 전체 총기 3자루면 0°/120°/240°, 4자루면 0°/90°/180°/270°에 배치된다. 원형 배치 위치 변화는 개별 조준과 간섭하지 않는다.
- [ ] 원형 배치의 실제 손 무기는 손 본에 남고, 부유 무기만 로컬 원형 슬롯에 배치된다.
- [ ] 주무기를 판매/해제하면 진화 → 고유 무기 → 최고 레벨 → 인스턴스 ID(먼저 장착) 순서로 자동 승계되며, 수동 주무기 지정이 가능하다.
- [ ] 주무기가 없는 경우 공격이 정지되고 이후 재장착 시 새 주무기가 지정된다.
- [ ] 시작 무기는 판매할 수 있고, 판매 자체로 고유 아이템 디버프가 발동하지 않는다.
- [ ] 고유 아이템 탈착 또는 Storage 이동 시 버프와 더 큰 디버프가 1회 적용되고, 재장착 시 모두 제거된다.
- [ ] 고유 아이템 판매 후 탈착 상태가 유지되고, 연속 보상 정리 과정에서 중복 적용되지 않는다.
- [ ] 전투 조끼 +2칸 회수 시 점유 셀이 있으면 판매/탈착 확정을 막고 재배치를 유도한다.

- [ ] 시작 무기 포함 모든 무기는 플레이어 중심 360° 원형 감지 반경 내 최근접 적을 찾고, 뒤쪽 적도 거리 내면 탐지한다.
- [ ] 추가 장착 무기는 캐릭터 옆에 떠 있으며 자기 감지 범위 안의 최근접 적을 **독립 조준·발사**하고 몸통을 회전시키지 않는다.
- [ ] 직접 든 시작 무기를 기준으로만 캐릭터가 부드럽게 회전하고 WASD 이동이 유지된다.
- [ ] 회전 애니메이션이 완료되지 않아도 발사 준비가 되었으면 표적 방향으로 사격한다. 회전으로 인한 발사 지연·데미지/정확도 디버프가 없으며, 총구와 탄 궤적이 시각적으로 자연스럽다.
- [ ] 추가 권총/샷건/미니건이 서로 다른 적을 조준해도 타이머·피격·방향이 간섭하지 않는다.
- [ ] 표적이 이동하면 이미 발사된 권총·샷건·미니건 투사체가 추적하지 않아 빗나갈 수 있다.
- [ ] 플레이어가 조준 방향을 바라보면서도 WASD 이동이 정상 동작한다.
- [ ] 권총은 정확히 설정한 간격에 자동 발사하며 장전하지 않는다.
- [ ] 샷건은 부채꼴 내부에서 펠릿을 일정 각도 간격으로 발사하고 짧은 거리에서 전량 반환한다.
- [ ] 샷건 동일 발사 펠릿 적중 수가 많을수록 넉백은 증가하며, 승인한 상한/점감 방식에 따라 과도한 밀림이 억제된다. 보스에는 저항 배율이 적용된다.
- [ ] 미니건은 설정한 속도로 연사, 100발 뒤 5초 재장전, 재장전 중 발사하지 않는다.
- [ ] 권총·미니건 탄은 Game View 밖으로 나간 즉시 반환되고, 경계 바깥 접촉으로 피해·관통·넉백·처치 효과가 발생하지 않는다.
- [ ] Lv.3 권총 1인스턴스는 2자루, 같은 권총 Lv.3 2인스턴스는 총 4자루 효과를 독립 실행한다.
- [ ] 샷건 Lv.3 넉백 요청과 Flow Field/Separation 이동 로직이 서로 값을 덮어쓰지 않는다.
- [ ] 미니건 Lv.3/헤비거너/냉각기 적용 시 각도 감소가 실제 탄퍼짐에 반영된다.
- [ ] 진화 권총의 난사 10초 쿨다운·3초 지속이 설정값대로 진행되며 UI 일시정지 시 시간이 멈춘다.
- [ ] 진화 샷건은 4초마다 XZ 평면 360° 방사, 기본 산탄은 강화된 범위/거리 사용.
- [ ] 진화 미니건 한 탄환이 서로 다른 적 3마리까지만 피해를 주고 같은 적 중복 콜라이더는 1마리로 집계한다.
- [ ] 진화 미니건은 승인한 정책에 따라 일반 상태보다 탄환 수가 증가한다.
- [ ] 무기 2개 장착 시 탄창·발사·스킬 타이머가 서로 독립적으로 동작한다.
- [ ] 보관(Storage) 중인 무기는 발사하지 않고, 장착/합성/판매/진화 후 확정된 전투 수치만 적용한다.
- [ ] 레벨업/보물상자/연속 레벨업 중 탄환 및 재장전·스킬 타이머가 멈추고, 마지막 완료 시 정상 이어진다.
- [ ] 장시간 다수 탄환 발사 시 풀 객체 누수, GC 급증, 중복 피격/중복 반환이 없는지 Profiler로 확인한다.

## 13. 구현 전에 결정할 주요 항목

1. **발사 순간 무기 비주얼:** 캐릭터 몸통은 부드럽게 회전하지만 총구는 즉시 표적 방향을 향하도록 독립 피벗을 둘지. 실제 탄환은 유효 표적이 감지되고 기존 발사 조건이 충족되면 회전 완료를 기다리지 않고 발사한다는 규칙이 확정됨.
2. **주무기 전환 연출:** 주무기 자동 승계/수동 지정과 원형 슬롯 재배치의 시각적 전환 시간·겹침 해소 방식(승계 우선순위/원형 균등 배치 자체는 확정).
3. **권총 총기 수:** Lv.3의 2자루 및 진화 4자루를 동시에 발사할지 교대 발사할지(동시 발사 제안).
4. **권총 난사 쿨다운:** 종료 후 10초 대기(현행 제안)인지 발동 시작 기준 10초인지.
5. **샷건 넉백 누적:** 펠릿 수 집계 시점, 상한/점감 방식(또는 둘 다), 보스 저항 배율.
6. **미니건 진화 탄환 수 증가:** 발사당 탄수 또는 연사속도 중 무엇을 늘릴지와 기본 증가량.
7. **진화 부가 정책:** 샷건 방사탄에 넉백을 적용할지, 진화 직후 특수 공격 첫 발동 시점.
8. **고유 아이템 탈착 최종 밸런스:** 제안 수치의 유효 손해량 검증, 전투 조끼 +2칸 회수 대상/충돌 처리 승인, 효과 중첩 순서.
