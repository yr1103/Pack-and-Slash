# Github Issue 등록

> 이 스킬은 **절차와 멘트 규격**만 정의한다.
>
> 작성 규칙과 양식의 원본은 아래 문서이며, 이 스킬에 규칙을 복사하지 않는다. (규칙 단일출처 유지)
>
> - 작성 규칙 : `Docs/Documentation/GithubIssueRules.md`
> - 작성 양식 : `Docs/Template/Issue Template.md`
> - 상위 흐름 : `Docs/Codex/WorkflowRules.md`의 `## 2. Github Issue`

---

## 절차

각 단계는 이전 단계가 완료되어야 진행한다. 단계를 건너뛰지 않는다.

### 1. 등록 권유

- 사용자가 직접 이슈 작성을 요청한 경우 이 단계는 생략한다.
- 이슈 등록이 필요하다고 판단하면 `[멘트 A] 등록 권유` 규격으로 권유하고, 사용자의 답을 기다린다.

### 2. 규칙 로드

- 작성 전 아래 문서를 읽는다.
    - `Docs/Documentation/GithubIssueRules.md` : `1. Title` ~ `7. 기타 (Label)` 섹션
    - `Docs/Template/Issue Template.md` : 양식 코드 블록
- 이전에 읽은 기억에 의존하지 않고, 매 호출마다 다시 읽는다.

### 3. 배경 / 목적 질문

- `GithubIssueRules.md`의 `2. 배경 / 목적` 규칙에 따라, `[멘트 B] 배경 / 목적 질문` 규격으로 사용자에게 질문한다.
- 사용자의 답이 없거나 불충분하면 이슈 작성을 진행하지 않는다.

### 4. 초안 작성 및 승인 요청

- 2단계에서 읽은 규칙과 양식에 따라 초안을 작성한다.
- `[멘트 C] 초안 승인 요청` 규격으로 제시하고, 사용자의 승인을 기다린다.
- 수정 요청이 있으면 해당 부분만 고쳐 다시 `[멘트 C]`로 제시한다.

### 5. 등록

- 승인을 받은 후에만 등록한다.
- 본문은 스크래치패드 경로에 임시 파일로 저장한 뒤 `gh` CLI로 등록한다.
    ```
    gh issue create --title "<Title>" --body-file "<임시 파일 경로>" --label "<Label>"
    ```
- 등록 후 `[멘트 D] 등록 완료` 규격으로 보고한다.
- 이후 사용자의 `착수명령`이 있을 때까지 대기한다. (`WorkflowRules.md` `2. Github Issue`)
- `착수명령`을 받으면 `WorkflowRules.md` `2. Github Issue`의 Assignees 규칙에 따라 담당자를 지정한다.

## 멘트 규격

> 필요한 정보만 간결하게 전달한다. 규격 외의 설명은 덧붙이지 않는다.

### [멘트 A] 등록 권유

```markdown
📌 **이슈 등록 권유**
- 사유 : (이슈가 필요한 이유 한 줄)
- 유형 : 개발 / 버그수정
- 예상 Label : (Label 하나)

이슈를 작성할까요?
```

### [멘트 B] 배경 / 목적 질문

```markdown
❓ **배경 / 목적 확인**
- 이 작업이 필요해진 배경은 무엇인가요?
- 작업으로 해결하려는 목적은 무엇인가요?

(이해한 내용이 있으면 한 줄로 요약해 함께 제시)
```

### [멘트 C] 초안 승인 요청

```markdown
📝 **이슈 초안 : (Title)**
- Label : (Label)
- 핵심 : (목표 1~2줄 요약)

(Issue Template 양식에 따른 본문)

이대로 등록할까요? 수정할 부분이 있으면 말씀해 주세요.
```

### [멘트 D] 등록 완료

```markdown
✅ **이슈 등록 완료** : #(번호) (Title)
- 링크 : (이슈 URL)

착수명령이 있을 때까지 대기합니다.
```
